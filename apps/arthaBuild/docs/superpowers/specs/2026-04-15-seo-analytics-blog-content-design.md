# ArthaBuild — SEO, Analytics, Blog & Content Strategy
**Date:** 2026-04-15  
**Status:** Approved  
**Approach:** Approach A — Exact TechCloudPro port adapted for FastAPI/EC2 stack  

---

## Overview

This spec covers the full content marketing and SEO system for artha.build at launch. The goal is to own the "NetSuite AI automation" niche in Google from day one — a niche that is currently nearly empty. The system consists of five interconnected layers: SEO infrastructure, custom analytics, a blog with 84 posts across 4 clusters, 6 industry/solutions pages, and a content strategy with distribution playbook.

**No customer names are used anywhere.** All content references industry and vertical only.

---

## Architecture Decision

**Approach A — React SPA + react-helmet-async + FastAPI analytics endpoint.**

Port TechCloudPro's exact patterns (SEO.tsx, SchemaMarkup.tsx, useAnalytics hook) adapted for ArthaBuild's FastAPI/nginx/EC2 stack. Analytics posts to `/api/analytics/collect` instead of PHP. Blog and industry pages backed by TypeScript data files. No SSR, no prerendering at launch — TCP ranks well with identical setup and the NetSuite AI niche has near-zero competition.

## Section 1: SEO Infrastructure

### Component Placement

`SEO.tsx` and `SchemaMarkup.tsx` go in a new `src/frontend/src/components/ui/` subdirectory — this subdirectory does not currently exist and must be created. This establishes a UI utility components convention consistent with TechCloudPro's structure. Future shared UI primitives (e.g., `GlassCard`, `SectionHeader`) can move here over time.

### New Frontend Files

**`src/frontend/src/components/ui/SEO.tsx`**  
react-helmet-async component. Renders per page: `<title>`, `<meta name="description">`, `<link rel="canonical">`, Open Graph tags (title, description, url, type, image), Twitter card tags. Configured for domain `artha.build`. Default OG image: `/og-image.png` (1200×630px, dark background `#030308`, ArthaBuild logo + tagline, consistent with landing page aesthetic). **This image must be created and added to `public/` as part of implementation scope.**

```ts
interface SEOProps {
  title: string
  description: string
  path: string
  type?: 'website' | 'article'
  image?: string
}
```

**`src/frontend/src/components/ui/SchemaMarkup.tsx`**  
JSON-LD structured data via react-helmet-async. Schemas emitted per page:

| Page type | Schemas |
|-----------|---------|
| All pages | `SoftwareApplication` (ArthaBuild product), `WebSite` |
| Blog list | `BreadcrumbList` |
| Blog post | `Article`, `BreadcrumbList` |
| Industry page | `Service`, `BreadcrumbList` |
| Solutions hub | `BreadcrumbList` |

`SoftwareApplication` schema:
```json
{
  "@type": "SoftwareApplication",
  "name": "ArthaBuild",
  "applicationCategory": "BusinessApplication",
  "description": "AI-powered NetSuite development platform. Generates, tests, and deploys SuiteScript inside your AWS VPC.",
  "url": "https://artha.build",
  "offers": { "@type": "Offer", "price": "799", "priceCurrency": "USD" }
}
```
Note: `operatingSystem` is omitted — the schema.org property only accepts consumer OS values (Windows, macOS, Web, iOS, Android). "AWS" is not a valid value and fails Google's Rich Results Test.

**`src/frontend/public/robots.txt`**
```
User-agent: *
Allow: /
Disallow: /dashboard
Disallow: /chat
Disallow: /profile
Disallow: /settings
Disallow: /admin
Sitemap: https://artha.build/sitemap.xml
```

**`src/frontend/public/sitemap.xml`**  
Static XML. Covers 95 public URLs: `/` (1) + `/blog` (1) + `/blog/{slug}` × 84 + `/solutions` (1) + `/solutions/{industry}` × 6 + `/privacy` (1) + `/terms` (1) = 95 total. Priority: `/` = 1.0, industry pages = 0.9, `/blog` + `/solutions` = 0.9, blog posts = 0.8. Each blog post entry includes `<lastmod>` from the post's `publishedAt` field (ISO date string, see Blog Data Structure). Generated by `scripts/generate-sitemap.ts` invoked via a `postbuild` npm script in `package.json` (`"postbuild": "tsx scripts/generate-sitemap.ts"`). Requires adding `tsx` to devDependencies.

**nginx cache note:** The existing nginx `location ~* \.(?:js|css|woff2?|png|jpg|svg|ico)$` static regex does not include `.txt` or `.xml`. Extend it to `\.(?:js|css|woff2?|png|jpg|svg|ico|txt|xml)$` so `robots.txt` and `sitemap.xml` get long-lived cache headers. Without this they fall through to the `location /` block and get `no-store` headers.

### Dependencies

- `react-helmet-async` — add to `src/frontend/package.json`
- `tsx` — add to `src/frontend/devDependencies` (runs `generate-sitemap.ts` at build time)
- `HelmetProvider` wraps the app root in `src/frontend/src/main.tsx`

### Scope

`<SEO>` and `<SchemaMarkup>` added only to public routes: `/`, `/blog`, `/blog/:slug`, `/solutions`, `/solutions/:industry`, `/privacy`, `/terms`. Authenticated routes excluded — Google cannot index them.

### Privacy Policy Update

Add one paragraph to `PrivacyPolicy.tsx` disclosing the self-hosted analytics endpoint. Framed as a privacy advantage: no third-party trackers, no cookies, data stays on ArthaBuild's own infrastructure.

## Section 2: Analytics

### Frontend — `src/frontend/src/hooks/useAnalytics.ts`

Custom hook using React Router's `useLocation`. Fires on every public route change. Tracks:

- **Pageviews** — route, referrer, session ID, UTM params
- **Scroll depth** — 0–100%, via passive scroll listener, updates per page
- **Time on page** — seconds, sent on route change and page unload via `pagehide`
- **Events** — exported `trackEvent(element, eventType, value)` for CTA clicks

Posts JSON to `POST /api/analytics/collect` using `navigator.sendBeacon` (with `fetch` keepalive fallback). No cookies. Session ID stored in `sessionStorage` only. UTM params persisted in `sessionStorage` across navigation.

**Only fires on public routes.** Excluded from all authenticated routes as defined in `routes.tsx`: `/dashboard`, `/chat/*`, `/history`, `/profile`, `/settings`, `/help`, `/guide`, `/admin`, `/admin/*`, `/mfa-setup`. Also excluded: `/oauth/callback`, `/accept-invite`, `/verify-email` (sensitive post-auth flows). Implementation rule: maintain an explicit `EXCLUDED_PATHS` array in the hook rather than relying on route wrapper checks, so the exclusion list stays visible in one place.

### Backend — `src/backend/routers/analytics.py`

New FastAPI router mounted at `/api/analytics`.

**`POST /api/analytics/collect`** — public, no auth.  
Payload: `type` (pageview | update | event), `session_id`, `page`, `referrer`, `scroll_depth`, `time_on_page`, optional UTM fields.  
Writes to `analytics_events` SQLite table via new Alembic migration.  
Rate limited: 60 requests/minute per IP (FastAPI `slowapi` limiter already in project).

**`GET /api/admin/analytics/summary`** — admin auth required via `require_admin` from `auth_utils.py` (same pattern as all other `/api/admin/*` endpoints). Not the `ADMIN_SECRET_KEY` header path.  
Returns: daily pageviews (last 30 days), top 10 pages, top 10 referrers, UTM campaign breakdown.  
Consumed by new Analytics tab in `AdminPanel.tsx`.

### Database — Alembic Migration

New table `analytics_events`:
```sql
id          INTEGER PRIMARY KEY
type        TEXT NOT NULL        -- pageview | update | event
session_id  TEXT NOT NULL
page        TEXT NOT NULL
referrer    TEXT
scroll_depth INTEGER DEFAULT 0
time_on_page INTEGER DEFAULT 0
utm_source  TEXT
utm_medium  TEXT
utm_campaign TEXT
utm_term    TEXT
utm_content TEXT
event_type  TEXT                 -- for type=event
element     TEXT
value       TEXT
created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
```

### Blog Data Structure

**`src/frontend/src/data/blog.ts`:**
```ts
export type BlogCategory = 'netsuite' | 'cost' | 'ai-erp' | 'engineering'

export type EditorialBadge = 'must-read' | 'hot' | 'deep-dive' | 'quick-win'

export interface BlogPost {
  slug: string
  title: string
  description: string
  category: BlogCategory
  badge?: EditorialBadge
  publishedAt: string   // ISO date string e.g. "2026-04-15" — NOT rendered in UI
  readTime: string
  tags: string[]
  content: string       // full HTML string
}

export const categories = [
  { id: 'all', label: 'All' },
  { id: 'netsuite', label: 'NetSuite How-To' },
  { id: 'cost', label: 'Cost & ROI' },
  { id: 'ai-erp', label: 'AI for ERP' },
  { id: 'engineering', label: 'Engineering' },
]
```

`publishedAt` is required in the data type but **never rendered in the UI**. It feeds two places only: the `Article` JSON-LD `datePublished` field (Google structured data requirement) and the sitemap `<lastmod>` tag per blog URL. All 84 posts use `"2026-04-15"` at launch. No `author` or `authorTitle` fields.

## Section 6: Content Strategy — Storyline, Quality & Outreach

### The Launch Narrative

Every post connects to one of four beats:

> 1. NetSuite customization costs too much and takes too long
> 2. Generic AI (ChatGPT) makes it worse — it hallucinates SuiteScript that breaks your ERP
> 3. ArthaBuild is purpose-built for NetSuite — runs in your AWS, data never leaves
> 4. Here is everything you need to know (blog) + here is what it does for your industry (solutions)

### Content Quality Standards

Every blog post must include:

| Standard | Requirement |
|----------|------------|
| Specific headline | Opinionated, concrete, benefit-driven. No generic titles. |
| Real numbers in intro | Cost figure or stat in the first 3 sentences |
| Rich formatting | At least one: table, blockquote, code block (where relevant) |
| Key Takeaway | Callout box at end — encourages bookmarking and sharing |
| Internal link | One link to a related blog post |
| Industry link | One link to relevant `/solutions/{industry}` page |
| End CTA | "See how ArthaBuild handles this →" → `/create-account` |
| Length | 800–1,500 words for standard posts; 2,000+ for MUST READ pillar posts |

### Pillar + Cluster Structure

One MUST READ pillar per cluster. Supporting posts link to pillar. Pillar links to supporting posts. Example:

```
Pillar: "The Complete Guide to NetSuite SuiteScript 2.1 (2026)"
  └── "SuiteScript Scheduled Scripts Explained"
  └── "SuiteScript Map/Reduce Scripts for Large Data Sets"
  └── "10 SuiteScript Errors and How to Fix Them"
  └── "SuiteScript vs Workflow: When to Use Which"
```

### Attribution & Dates

- **Author:** "ArthaBuild" brand only. No individual names anywhere.
- **Dates:** Not rendered in UI. Present only in sitemap.xml and Article JSON-LD (for Google).
- **Editorial badges:** Replace dates as the value signal on cards (MUST READ, HOT, DEEP DIVE, QUICK WIN).

### No Customer Names Policy

Industry and vertical only — always. Never name a specific company, client, or organization in any blog post, industry page, distribution message, or outreach material.

### Distribution Channels

| Channel | Content type | Approach |
|---------|-------------|---------|
| LinkedIn | All clusters | Post excerpt + link, tag NetSuite community |
| Reddit r/Netsuite | NetSuite How-To, Cost | Share as genuine value, not promotion |

On Hashnode: article → Settings → "Are you republishing?" → enter canonical URL. Without this, Google will treat the cross-post as duplicate content. |
