1. What We Are Building

ArthaBuild is an AI-powered NetSuite development platform that runs entirely inside the customer's AWS VPC. It automates the full SuiteScript lifecycle: describe in English → AI generates SuiteScript → review in chat → type "yes" → deployed to NetSuite automatically.


Core principle: Zero external data transfer. Every customer gets their own deployment inside their own AWS account. NetSuite credentials, SuiteScript code, and questions never leave their VPC. AI runs locally on Ollama.

Before ArthaBuild

  • Consultant writes SuiteScript manually → 2–5 days
  • Deployment requires SuiteCloud CLI expertise → 1 day
  • NetSuite bugs → back-and-forth with support → weeks

With ArthaBuild

  • Describe what you need → script generated in seconds
  • Review in chat → type "yes" → auto-deployed
  • Ask any NetSuite question → 203,618-chunk knowledge base

5. Bug Fixes — Session 2 (2026-04-09)

All bugs found during live use after Phase 6 completed. Patched in-place across Phase 3 and Phase 4 files.

Fixed Chat stuck: "Select or start a chat" — React state race Phase 4
Root cause: getChat(id) reads from chats React state which starts as [] on mount. Token effect ran before useChat init populated the state → null → redirect to /chat/new → infinite loop. Also: chatService saves to "arthalight_chats_v1" but fetchChats() reads "mock_chats_v1" — different localStorage keys.
→ Token effect now uses chatService.getById(id) (synchronous localStorage, no race). activeChat useMemo also reads chatService.getById() as primary source. Added token === "new" guard.
src/frontend/src/pages/Chat.tsx
Fixed SuiteScript response blanked screen — JSON.parse crash Phase 4
Root cause: code.includes('[') matched JavaScript array literals (var filters = []) in generated SuiteScripts → JSON.parse(code) threw SyntaxError on valid JS → React crashed with no error boundary → blank screen.
→ Changed condition to code.trim().startsWith('[') && (JSON.parse in try-catch returns true). Upgraded else fallback to use SyntaxHighlighter — SuiteScript now renders with proper JS/XML syntax highlighting.
src/frontend/src/components/ChatMessage.tsx
Fixed "how to deploy this" → "Request failed" — SystemExit from SuiteCloud CLI Phase 3
Root cause: infer_intent() classified "deploy" as manage_sdf_project → handle_sdf_project() called suitecloud project:deploy (not installed) → run_command() called sys.exit(1) → SystemExit raised → NOT caught by except Exception → uvicorn worker killed.
→ Added _suitecloud_ready guard. Changed outer catch to except BaseException (catches SystemExit). When SuiteCloud not ready, RAG answer is returned instead.
src/backend/rawapi.py
Fixed "yes" always returned "No valid code blocks found" Phase 3
Root cause: After appending user "yes" and the RAG response to chat_sessions, chat_sessions[-1] pointed to the RAG response to "yes" (not the prior SuiteScript). save_generated_files() received plain text with no code blocks → always failed.
→ Now searches backwards through history[:-2] for the last assistant message containing triple-backtick code blocks. Correct SuiteScript is always found.
src/backend/rawapi.py
Fixed fetch_netsuite_data / download functions returned None Phase 3
Root cause: download_suitescript_file() and extract_custom_suitescript_metadata() had except CalledProcessError blocks with no return statement → implicit None return → {"response": null} sent to frontend.
→ Added return "❌ ..." to both except blocks. Added None-fallback guard in rawapi.py before setting response_text.
src/backend/suitescripts_utils.py src/backend/rawapi.py
Fixed graph.invoke() result not guarded against None Phase 3
Root cause: result.get("generation", "") called unconditionally — crashes with AttributeError if graph.invoke() returns None.
→ Changed to (result.get("generation", "") if isinstance(result, dict) else "") or "I could not find..."
src/backend/rawapi.py
Fixed 500 errors showed "Request failed" — key mismatch Phase 3+4
Root cause: Backend 500 errors returned {"error": str(e)} but api.ts read err.detail → always undefined → generic "Request failed".

6. Chatbot Response Reliability Rules (v1.5 — permanent)

Derived from Session 2 bug fixes. All future changes to /api/chatbot/process or chat rendering must comply.

🚫
Never return None as response_textAll intent handlers must return a string. Add or "❌ ..." fallback if function can return None.
🛡
graph.invoke() must be guardedAlways isinstance(result, dict) check before .get("generation").
🔒
manage_sdf_project requires _suitecloud_readyNever call handle_sdf_project() unless _suitecloud_ready is True. RAG answer is the fallback.
⚠️
except BaseException in chatbot handlerSuiteCloud CLI calls sys.exit(1) → raises SystemExit → not caught by except Exception.
📋
500 error key must be "detail"Frontend reads err.detail. Backend must use {"detail": str(e)}, not {"error": str(e)}.
🔍
"yes" handler must search backwardsFind last assistant message with ``` code blocks via reversed(history[:-2]), never a hardcoded index.
🧹
JSON array detection must use startsWith + try-catchOnly treat code block as JSON if code.trim().startsWith('[') && JSON.parse succeeds. Never code.includes('[').
⚡
