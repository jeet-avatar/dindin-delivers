1f. Add `GET /api/user/verify-email`:
```python
@router.get("/verify-email")
async def verify_email(
    token: str,
    db: AsyncSession = Depends(get_db),
):
    token_hash = hash_token(token)
    result = await db.execute(
        select(EmailVerificationToken).where(EmailVerificationToken.token_hash == token_hash)
    )
    vtoken = result.scalar_one_or_none()
    if not vtoken or vtoken.used:
        raise HTTPException(status_code=400, detail="Invalid or already-used verification link")
    if vtoken.expires_at < datetime.now(timezone.utc):
        raise HTTPException(status_code=400, detail="Verification link has expired")
    # Mark used + set is_verified on user
    vtoken.used = True
    user_result = await db.execute(select(User).where(User.id == vtoken.user_id))
    user = user_result.scalar_one_or_none()
    if user:
        user.is_verified = True
    await db.commit()
    return {"message": "Email verified successfully"}
```

async def require_user(

CRITICAL: Because FastAPI uses Depends() to inject require_user, the `require_verified` parameter will default to True for all existing endpoints (backward compatible). Endpoints that need to work for unverified users (verify-email, resend-verification, GET /me, change-password) must explicitly use `Depends(lambda db=Depends(get_db), creds=Depends(_bearer_scheme): require_user(creds, db, require_verified=False))`. However, this lambda approach has FastAPI DI issues. The cleaner approach: add a `require_user_unverified_ok` alias:

```python
async def require_user_unverified_ok(
    credentials: HTTPAuthorizationCredentials = Depends(_bearer_scheme),
    db: AsyncSession = Depends(get_db),
) -> User:
    """Like require_user but does NOT enforce email verification."""
    return await require_user(credentials=credentials, db=db, require_verified=False)
```
