```markdown
## Phase 11: Password Management — Enterprise Email Flow

### 11.1 Overview
Upgrades password management from Phase 1 scaffolding (plain-text emails, 1-hour tokens, no enforcement) to enterprise-grade. Adds HTML transactional email templates (Linear/Vercel style), 15-minute reset token expiry, email verification enforcement, a full set of user account endpoints, and admin-triggered resets.

### 11.2 New DB Model
**EmailVerificationToken** (email_verification_tokens table)
- Alembic migration: c4d5e6f7a8b9
- Fields: id, user_id (FK → users, CASCADE), token_hash (SHA-256, unique), expires_at (24h), used, created_at
- Same SHA-256 hashing pattern as PasswordResetToken

### 11.3 Email Templates (email_utils.py)
- `_render_reset_email_html()` — password reset HTML email (white bg, indigo button, fallback URL, 15min expiry notice)
- `_render_verification_email_html()` — click-to-verify HTML email (24h expiry)
- `_render_admin_reset_email_html()` — admin-triggered reset HTML email (notes admin initiation)
- All templates: inline styles only (no `<style>` blocks — email client compatibility)
- `token_expiry()` changed from 1hr → 15min

### 11.4 New Backend Endpoints (routers/user.py)
| Endpoint | Auth | Description |
|----------|------|-------------|
| GET /api/user/me | Bearer (unverified OK) | Profile + is_verified status |
| PATCH /api/user/me | Bearer (unverified OK) | Update first_name / last_name |
| DELETE /api/user/me | Bearer (unverified OK) | Soft-delete account + blacklist JTI |
| POST /api/user/change-password | Bearer (unverified OK) | Verify old pw + set new pw |
| GET /api/user/verify-email | Public (token param) | Consume EmailVerificationToken, set is_verified=True |
| POST /api/user/resend-verification | Public (rate-limited 3/min) | Invalidate old + issue new verification token |

### 11.5 Admin Reset Endpoint (routers/admin.py)
| Endpoint | Auth | Description |
|----------|------|-------------|
| POST /api/admin/users/{id}/send-reset | Bearer (admin) | Trigger password reset email for team member + write audit log |
- Team-scoped: returns 404 if user_id is not on admin's team

### 11.6 Auth Middleware Update (auth_utils.py)
- `require_user()` now checks `user.is_verified` — raises HTTP 403 with `{"error":"email_not_verified"}` for unverified users
- `require_user_unverified_ok` alias exported — used by /me, change-password, resend-verification endpoints to allow unverified access

### 11.7 Frontend Components
- **EmailVerificationBanner.tsx** — Persistent amber banner for unverified users. Polls GET /api/user/me on mount. Resend button with 60s cooldown. Dismissible via X button. Placed in Chat.tsx alongside LicenseBanner.
- **VerifyEmail.tsx** — Public page at /verify-email?token=... Calls GET /api/user/verify-email. Shows success or error+resend.
- **Profile.tsx** — Extended with Change Password form (old/new/confirm fields, full policy validation matching backend).
- **ResetFailed.tsx** — Replaced navigate-away button with inline resend form + 60s cooldown.
- **ForgotPassword.tsx** — Removed dev token shortcut nav; shows "check your inbox" success state.
- **ResetPassword.tsx** — Password validation updated from 6-char minimum to full policy (8+, upper, lower, digit, special).

### 11.8 Test Coverage
- test_user.py extended with CASE-181/184/185/186/187 tests
- CASE-182 (password history) and CASE-183 (90-day expiry) deferred — out of scope per CONTEXT.md
- conftest.py: valid_reset_token fixture expiry updated from 1hr → 15min
- conftest.py: auth_tokens fixture sets is_verified=True to prevent 403 in existing test suite
- Final test count: [FILL FROM ACTUAL RUN] tests passing
```
