**Step 1 — WAF Managed Rules (SEC-CF-02):**
Use `http_request_firewall_managed` phase + execute action. Deploy in LOG mode first to catch false positives from SuiteScript/SQL patterns in chatbot messages.

NOTE: Ruleset IDs are global Cloudflare constants (not zone-specific):
- CF Managed Ruleset: `efb7b8c949ac4650a09736fc376e9aee`
- OWASP Core Ruleset: `4814384a9e5d4991b9815dcfc25d2f1f`

```bash
echo "=== Step 1: Deploy WAF Managed Rules (LOG mode — review before switching to block) ==="
# Get or create entry point ruleset
ENTRY_RULESET=$(curl -s "$BASE/zones/$ZONE_ID/rulesets/phases/http_request_firewall_managed/entrypoint" \
  -H "Authorization: Bearer $CF_API_TOKEN" | jq -r '.result.id // empty')

# Deploy Cloudflare Managed Ruleset (available on Free plan too, limited subset)
curl -s -X POST "$BASE/zones/$ZONE_ID/rulesets/$ENTRY_RULESET/rules" \
  -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "action": "execute",
    "action_parameters": {"id": "efb7b8c949ac4650a09736fc376e9aee"},
    "expression": "true",
    "description": "Cloudflare Managed Ruleset — LOG mode",
    "logging": {"enabled": true},
    "enabled": true
  }' | jq '.success'

# Deploy OWASP CRS only if Pro or above
if [ "$WAF_FULL" = true ]; then
  curl -s -X POST "$BASE/zones/$ZONE_ID/rulesets/$ENTRY_RULESET/rules" \
    -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
    -d '{
      "action": "execute",
      "action_parameters": {"id": "4814384a9e5d4991b9815dcfc25d2f1f", "version": "latest"},
      "expression": "true",
      "description": "OWASP Core Ruleset — LOG mode (switch action to block after reviewing logs)",
      "logging": {"enabled": true},
      "enabled": true
```

**Step 2 — Security headers via Transform Rules (SEC-CF-06):**
CRITICAL: Only add Permissions-Policy and enforcing CSP — do NOT add HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy (nginx.prod.conf already sets these). Adding them in Cloudflare would result in duplicate headers.

CSP enforcing value must match what nginx.prod.conf uses in Report-Only mode (line 36).

```bash
echo "=== Step 2: Add security headers via Transform Rules (additive only — no nginx duplicates) ==="
curl -s -X POST "$BASE/zones/$ZONE_ID/rulesets" \
  -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "name": "artha.build security headers",
    "kind": "zone",
    "phase": "http_response_headers_transform",
    "rules": [
      {
        "description": "Add Permissions-Policy and enforcing CSP (not duplicating nginx headers)",
        "expression": "true",
        "action": "rewrite",
        "action_parameters": {
          "headers": {
            "Permissions-Policy": {
              "operation": "set",
              "value": "camera=(), microphone=(), geolocation=()"
            },
            "Content-Security-Policy": {
              "operation": "set",
              "value": "default-src '\''self'\''; script-src '\''self'\''; style-src '\''self'\'' '\''unsafe-inline'\''; img-src '\''self'\'' data:; connect-src '\''self'\''; frame-ancestors '\''none'\''"
            }
          }
        },
        "enabled": true
      }
    ]
  }' | jq '.success'
echo "NOTE: nginx.prod.conf sets Content-Security-Policy-Report-Only. Cloudflare now sets"
echo "the enforcing Content-Security-Policy. Both can coexist — report-only is informational."
```

**Step 3 — WAF Rate Limiting Rule (SEC-CF-05):**
Use WAF Rate Limiting Rules (simpler than Workers — no wrangler deployment needed). Free tier: 1 rule. Rate-limit /api/ at 60 req/min but exclude /api/chatbot/ which handles long AI inference chains.

```bash
echo "=== Step 3: WAF rate limiting rule — /api/auth/* and /api/* excluding chatbot ==="
curl -s -X POST "$BASE/zones/$ZONE_ID/rulesets" \
  -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "name": "artha.build rate limit",
    "kind": "zone",
    "phase": "http_ratelimit",
    "rules": [
      {
        "description": "Rate limit /api/ at 60 req/min per IP (exclude /api/chatbot — AI inference)",
        "expression": "(http.request.uri.path matches \"^/api/\") and not (http.request.uri.path matches \"^/api/chatbot/\")",
        "action": "block",
        "ratelimit": {
          "characteristics": ["ip.src"],
          "period": 60,
          "requests_per_period": 60,
          "mitigation_timeout": 600
        },
        "enabled": true
      }
    ]
  }' | jq '.success'
```
