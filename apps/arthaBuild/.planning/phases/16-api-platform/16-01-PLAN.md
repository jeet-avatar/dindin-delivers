<objective>
Add API key authentication, versioned /api/v1/ routing, webhook delivery, and standardised response envelope.

Purpose: Third-party integrations (Zapier, customer scripts, CI pipelines) need API keys (not user JWTs) to call ArthaBuild. Versioned routes let us ship breaking changes without breaking existing integrations. Webhooks push events to customer systems without polling.
Output: APIKey + WebhookEndpoint models, api_key_auth middleware, apikeys.py router, auth_utils.py fallback, response envelope middleware, webhook dispatch worker covering both chat.completed and script.deployed events.
</objective>

   - WebhookEndpoint model: id, user_id (FK users), event (String — e.g. "chat.completed", "script.deployed"), url (String), secret (String — HMAC signing secret), is_active (Boolean), created_at.

2. Write Alembic migration 16a_api_key_model.py: create api_keys + webhook_endpoints tables.
   - Run `alembic heads` first to confirm the current single-head revision ID. Set down_revision to that ID.
   - Use render_as_batch=True (project rule for SQLite ALTER TABLE compatibility).

3. Create routers/apikeys.py with prefix /api/v1/keys:
   - POST / — create API key: generate 32-byte secret (secrets.token_urlsafe), store SHA-256 hash in DB, return raw key ONCE in response (never stored raw).
   - GET / — list user's API keys (name, id, is_active, last_used_at — NOT the hash).
   - DELETE /{key_id} — deactivate (is_active=False).

4. Create middleware/api_key_auth.py (BaseHTTPMiddleware):
   - Check for X-API-Key header. If absent → call_next and pass through (JWT auth still applies).
   - If present: compute SHA-256 of value, SELECT FROM api_keys WHERE key_hash=hash AND is_active=True. If not found → return 401.
   - Update last_used_at on the key row.
   - Inject resolved user into request.state.api_key_user so downstream Depends can read it.

5. Modify auth_utils.py — update require_user() to fall back to request.state.api_key_user when no Bearer token is present:
   - Add `request: Request` parameter (import Request from fastapi if not already imported).
   - Change the opening guard from immediately raising 401 to: check `request.state` for `api_key_user`; if present, return it directly (skip JWT decode entirely).
   - Only raise 401 if both credentials is None AND request.state has no api_key_user.
   - This ensures all existing endpoints guarded by `Depends(require_user)` automatically accept X-API-Key requests once the middleware resolves the user.
   - Keep all existing JWT validation logic unchanged for the non-API-key path.

6. Register in rawapi.py:
   - app.add_middleware(APIKeyAuthMiddleware) — must be added AFTER CORSMiddleware so X-API-Key header passes through CORS first.
   - Include apikeys_router at /api/v1/keys.
   - Add a /api/v1/ router prefix alias for the chats router — same handler, different prefix — so v1 routes exist alongside legacy /api/ routes.
