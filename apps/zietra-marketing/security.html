Security at Zietra

Last updated: 2026-05-15 · Contact: security@zietra.com

Zietra is a multi-tenant SaaS platform serving SMBs across CRM, sales, purchasing, items management, manufacturing, quality, and finance domains. Every tenant's data lives behind the controls described below. We treat security as a continuously-measured discipline, not a one-time checkbox, and this page is kept up to date as our controls evolve.

1. Data residency

All customer data is stored in AWS us-east-1 (Northern Virginia). Aurora PostgreSQL clusters, S3 buckets, Secrets Manager secrets, and Lambda functions are all regionally pinned. Additional AWS regions will be added on the roadmap as regulated-industry customers require local residency (EU-West for GDPR-strict tenants, AP-South for India-specific compliance).

2. Encryption at rest

Every persistent store is encrypted with AES-256 using AWS KMS-managed keys.

  • Aurora PostgreSQL: StorageEncrypted=true on every cluster, KMS-managed.
  • S3 buckets: AES256 SSE on all customer-facing buckets; public access blocked at the account and bucket level.
  • Secrets Manager: every secret encrypted under a dedicated KMS key; service-specific IAM roles grant secretsmanager:GetSecretValue with least privilege.
  • EBS volumes attached to any compute (including the NAT instance): encrypted at rest by default.

3. Encryption in transit

TLS 1.2 or higher is enforced on every customer-facing endpoint. HSTS is enabled on all CloudFront distributions with a 1-year max-age. Browser traffic terminates at AWS Certificate Manager-issued certificates on CloudFront. Internal hops are also encrypted:

  • CloudFront → API Gateway / Lambda: TLS.
  • Lambda → RDS Proxy → Aurora: TLS with RequireTLS=true at the Proxy layer; Aurora requires SSL.
  • Lambda → AWS service endpoints (Secrets Manager, KMS, Cognito IDP): TLS over private VPC interface endpoints — never traverses the public internet.

4. Authentication

Customer authentication is provided by AWS Cognito. We do not store passwords. Sign-in is passwordless via magic-link emails delivered through Amazon SES; sessions are bound to short-lived RS256 JWTs verified against the Cognito JWKS at every request. SAML/SSO federation for Enterprise tenants is on the M8 roadmap. Administrative access to AWS infrastructure requires hardware MFA on every IAM principal.

5. Authorization

Role-based access control (RBAC) is enforced both in middleware and at the database layer.

  • Roles: admin, manager, member, viewer per tenant, stored in tenant_users.
  • Middleware: requireRole() middleware checks the JWT's tenant claim against the role required for each endpoint.
  • Schema isolation: each major tenant family lives in its own Postgres schema (turion, turion_satellite, crm, public).
  • Row-level security: PostgreSQL RLS policies enforcing tenant_id = current_setting('app.tenant_id') are on the M3 roadmap and will provide a second isolation layer behind schema separation.

6. Network isolation

Customer-facing compute and data planes are deployed inside a dedicated VPC (zietra-prod-vpc, 10.0.0.0/16) with strict subnet separation:

  • Public subnets host only the egress NAT and Internet Gateway path.
  • Private subnets host every Lambda, the RDS Proxy, and the Aurora cluster.
  • Aurora is PubliclyAccessible=false and accepts ingress on port 5432 only from the RDS Proxy security group — not from 0.0.0.0/0, not from any operator IP.
  • Three application security groups (lambda-sg, rds-proxy-sg, aurora-sg) enforce least-privilege transit at the SG layer.
  • AWS WAFv2 sits in front of every CloudFront-served customer property, applying AWS-managed rule groups (Common Rule Set, Known Bad Inputs, Amazon IP Reputation, Bot Control).

7. Threat detection

Continuous threat detection is provided by AWS GuardDuty (15-minute publishing cadence, S3 protection enabled). High-severity findings (severity ≥ 7.0) trigger an EventBridge rule that fans out to an SNS topic and pages our on-call inbox at security@zietra.com. AWS Security Hub aggregates findings against the AWS Foundational Security Best Practices standard and CIS AWS Foundations Benchmark v1.4. Triage runs at T+2h, T+24h, and T+48h after every new deploy.

8. Audit logging

Every application action is recorded.

  • Application audit: an audit_log table per schema captures user, tenant, action, target, and timestamp for every state-changing API call.
  • API access logs: API Gateway access logs and Lambda CloudWatch logs are retained for at least 30 days.
  • Infrastructure: AWS CloudTrail captures every control-plane API call account-wide.
  • Configuration drift: AWS Config records resource state changes on 18 targeted resource types (Lambda, RDS, S3, IAM, EC2 networking, CloudFront, WAFv2, KMS, Cognito, Secrets Manager) and writes deltas to a long-retention S3 bucket.

9. Backup and recovery

Aurora is configured for 7-day automated point-in-time recovery (backup retention period = 7 days). Manual snapshots are taken before every infrastructure migration and tagged for indefinite retention. Our objectives:

  • RPO (recovery point objective): < 5 minutes.
  • RTO (recovery time objective): < 30 minutes for a full Aurora restore from snapshot.
  • Rollback runbooks for every migration are version-controlled in .planning/runbooks/ with the exact commands, scenarios, and decision trees.

10. Incident response

Report a suspected security incident to security@zietra.com. Our targets:

  • Acknowledge: within 24 hours.
  • Initial triage and severity assignment: within 72 hours.
  • For confirmed HIGH/CRITICAL findings, affected customers receive direct notification within the timelines required by their applicable regulatory framework.
  • A PGP key for encrypted disclosures is forthcoming and will be linked from this page.

11. Compliance

Zietra's underlying infrastructure runs on AWS, inheriting the controls AWS attests under SOC 1/2/3, ISO 27001/27017/27018, PCI DSS, and HIPAA-eligible service designations. At the application layer:

  • SOC 2: control set deployed (encryption, access control, change management, monitoring, incident response). Type II observation window planned for the first enterprise customer requiring it.
  • GDPR: data export and right-to-erasure tooling at the tenant level; data processing addendum available on request.
  • HIPAA: every AWS service in our architecture is HIPAA-eligible; a BAA can be put in place for tenants subject to HIPAA.

12. Subprocessors and contact

Zietra uses the following subprocessors:

  • Amazon Web Services — infrastructure hosting (us-east-1; additional regions on roadmap).
  • Anthropic — AI inference for in-product copilots (US and EU datacenters).
  • Stripe — billing and subscription management (when enabled for a tenant).
