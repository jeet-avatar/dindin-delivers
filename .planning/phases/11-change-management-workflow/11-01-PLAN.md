Create `change_management.py` in the backend directory. Include:

**Models (SQLAlchemy, follow project_tracker.py pattern):**

1. `ChangeRequest` model with fields exactly as specified in 11-RESEARCH.md:
   - `id` (Integer PK), `cr_id` (String 15, unique, indexed, format CR-XXXX), `title` (String 500), `description` (Text), `change_type` (String 50, default "code" -- values: code/config/docs/infrastructure/manual), `status` (String 30, default "Draft"), `priority` (String 20, default "Medium")
   - `case_ids` (Text, comma-separated TC-XXXX IDs), `department_id` (Integer FK to departments.id, SET NULL on delete, indexed)
   - `requested_by` (String 200, email), `approved_by` (String 200), `approved_at` (DateTime), `rejection_reason` (Text)
   - `branch_name` (String 200), `pr_url` (String 500), `pr_number` (Integer), `ci_run_id` (String 100), `ci_status` (String 50)
   - `deploy_staging_at` (DateTime), `deploy_production_at` (DateTime)
   - `rollback_of_cr_id` (String 15)
   - `created_at`, `updated_at` (DateTime with defaults)
   - Relationships: `department` (to Department), `audit_entries` (to AuditLog, ordered desc by created_at)

2. `AuditLog` model:
   - `id` (Integer PK), `change_request_id` (Integer FK to change_requests.id, CASCADE, indexed)
   - `action` (String 50 -- status_change/approval/rejection/comment/pr_created/ci_update/deployed/rollback)
   - `actor_email` (String 200), `old_value` (String 100), `new_value` (String 100), `metadata_json` (Text)
   - `created_at` (DateTime, indexed)
   - Relationship back to ChangeRequest

**State Machine (dict-based, NOT a library):**

- `CM_STATUSES` list: Draft, Submitted, Under Review, Approved, In Progress, PR Created, CI Running, Staging, Production, Verified, Closed, Rejected
- `VALID_TRANSITIONS` dict mapping current_status -> set of allowed next statuses (as in research)
- `NON_CODE_TRANSITIONS` override for non-code changes: In Progress -> Staging directly (skip PR Created, CI Running)
- `TRANSITION_ROLES` dict mapping (from, to) -> list of allowed roles (system, dept_lead, super_admin)

**Pydantic Schemas:**
- `ChangeRequestCreate` (title, description, change_type, priority, case_ids list)
- `ChangeRequestUpdate` (title, description, priority -- partial update)
- `StatusTransition` (new_status, reason optional, metadata optional)
- `ChangeRequestResponse` (all fields + audit_entries)

**Helper functions:**
- `generate_cr_id(db)` -- queries max existing CR-XXXX and increments (like project_tracker.py case_id pattern)
- `log_audit(db, change_request_id, action, actor_email, details)` -- creates AuditLog entry, flushes but does NOT commit (caller commits)
- `get_approver_for_case(db, case_ids)` -- looks up department via first linked case's department_id, returns Department.lead_email
- `validate_transition(current_status, new_status, change_type, role)` -- checks VALID_TRANSITIONS (or NON_CODE_TRANSITIONS for non-code), checks TRANSITION_ROLES, raises HTTPException 400 on invalid

Import Department and ProjectCase from project_tracker (import the classes, not the module -- avoid circular imports). Use the same Base, engine, get_db pattern as project_tracker.py.

Add `Base.metadata.create_all(bind=engine)` at module level (after model definitions) following the project_tracker.py pattern so tables are created on import.

<task type="auto">
  <name>Task 2: Build all API routes for change request lifecycle</name>
  <files>apps/web/p2p-platform/backend/change_management.py, apps/web/p2p-platform/backend/main_new.py</files>
  <action>
Add API routes to `change_management.py` using an APIRouter with prefix `/api/admin/change-requests` and tags `["change-management"]`. These routes are protected by the existing `admin_auth_middleware` (covers all /api/admin/* paths).

**CRUD Routes:**

1. `POST /` -- Create change request. Accepts ChangeRequestCreate body. Generates CR-XXXX id. Auto-resolves department_id from first linked case_ids (via ProjectCase.department_id). Sets status="Draft". Logs audit entry "created". Returns the new CR.

2. `GET /` -- List change requests. Query params: status, department_id, change_type, requested_by, page (default 1), page_size (default 50). Returns paginated list with total count. Order by created_at desc.

3. `GET /pending-execution` -- Returns change requests with status "Approved" or "In Progress" (for GSD executor polling). Returns list ordered by priority then created_at.

4. `GET /{cr_id}` -- Get single change request with all audit entries eagerly loaded.

5. `PUT /{cr_id}` -- Update change request (title, description, priority). Only allowed in Draft status. Logs audit "updated".

**Lifecycle Routes:**

6. `POST /{cr_id}/submit` -- Draft -> Submitted. Validates transition. Auto-transitions to "Under Review" immediately (system transition). Logs both transitions. Returns updated CR.

7. `POST /{cr_id}/approve` -- Under Review -> Approved. Requires approver_email in body (dept lead). Records approved_by, approved_at. Logs audit "approval". Returns updated CR.

8. `POST /{cr_id}/reject` -- Under Review -> Rejected. Requires reason in body. Records rejection_reason. Logs audit "rejection". Returns updated CR.

9. `POST /{cr_id}/transition` -- Generic transition endpoint. Accepts StatusTransition body. Validates via validate_transition(). Use `with_for_update()` on the SELECT to prevent race conditions. Logs audit "status_change" with old/new status. Handles metadata (PR URL, CI run ID, deploy timestamps) -- if new_status is "PR Created", expect pr_url and branch_name in metadata; if "CI Running", expect ci_run_id; if "Staging", set deploy_staging_at; if "Production", set deploy_production_at. Returns updated CR.

**Audit Routes:**

10. `GET /{cr_id}/audit` -- Get audit log for a specific CR. Returns list of AuditLog entries ordered by created_at desc.

11. `GET /audit/export` -- CSV export of all audit log entries (follow project_tracker.py export_project_cases pattern). Columns: cr_id, action, actor_email, old_value, new_value, metadata, timestamp.

**Rollback Route:**

12. `POST /{cr_id}/rollback` -- Creates a NEW ChangeRequest that is a revert of the given CR. Sets rollback_of_cr_id to original CR's cr_id. Sets change_type to "code". Copies department_id from original. Status starts at "Draft" (must go through full approval flow per user decision). Logs audit "rollback_created" on the original CR. Returns the new rollback CR.

**All mutations** MUST wrap status change + audit log in a single db.commit() (never commit separately). Use `with_for_update()` on status transition queries to prevent race conditions.
