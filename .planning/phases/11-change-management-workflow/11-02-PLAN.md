Create 4 React components following the projectTracker/Main.tsx patterns exactly (Ant Design + Lucide React icons + axios via api.ts).

**Main.tsx** -- Tab container with 4 tabs:
- "All Requests" -- Ant Design Table with columns: CR ID, Title, Status (Tag with color), Change Type, Priority, Department, Requested By, Created At. Filters: status dropdown (all 12 statuses), department dropdown (fetched from /api/admin/departments), change_type dropdown. Pagination. Click row navigates to request detail.
- "New Request" -- Renders RequestForm component
- "Approvals" -- Renders ApprovalQueue component
- "Audit Log" -- Renders AuditLog component

Status Tag colors: Draft=default, Submitted=blue, Under Review=orange, Approved=green, In Progress=cyan, PR Created=purple, CI Running=geekblue, Staging=gold, Production=lime, Verified=success, Closed=default, Rejected=error.

**RequestForm.tsx** -- Ant Design Form:
- Title (Input, required, max 500 chars)
- Description (TextArea, optional)
- Change Type (Select: code/config/docs/infrastructure/manual, default code)
- Priority (Select: Low/Medium/High/Critical, default Medium)
- Linked Cases (Select multiple, searchable -- fetches cases from /api/admin/project-cases for autocomplete, displays as TC-XXXX tags)
- Submit button: POST to /api/admin/change-requests/, on success shows success message and switches to All Requests tab
- Save as Draft button: same POST but does NOT auto-submit

**ApprovalQueue.tsx** -- Shows requests with status "Under Review":
- GET /api/admin/change-requests/?status=Under Review
- Table: CR ID, Title, Priority (with color tag), Requested By, Created At
- Row expand or click shows description and linked case IDs
- Approve button: POST /{cr_id}/approve with approver_email (use current admin email from auth context or localStorage)
- Reject button: opens Modal with TextArea for rejection reason, POST /{cr_id}/reject
- Confirmation Modal before approve/reject actions

**AuditLog.tsx** -- Searchable audit log:
- GET /api/admin/change-requests/audit/export for CSV download (button)
- For per-CR audit, uses GET /{cr_id}/audit (shown in RequestDetail, not here)
- This is the global audit view: fetch all CRs, display flattened timeline of all audit entries across all CRs
- Search by CR ID, actor email, action type
- Ant Design Timeline component showing entries in reverse chronological order
- Export CSV button triggers download of /audit/export endpoint response

All components use `api.get()` / `api.post()` from the existing api.ts module (has auth interceptor). Follow TypeScript conventions from projectTracker/Main.tsx.

**RequestDetail.tsx** -- Single change request detail view:
- Fetches CR by cr_id from URL param: GET /api/admin/change-requests/{cr_id}
- Header: CR ID badge + Title + Status Tag (same colors as Main.tsx)
- Info section: Change Type, Priority, Department, Requested By, Created/Updated timestamps
- If rollback_of_cr_id is set, show "Rollback of: CR-XXXX" with link
- PR section (if pr_url set): link to PR, CI status badge, branch name
- Deploy section: staging deploy timestamp, production deploy timestamp

- **Action buttons** (conditional on status):
  - Draft: "Submit for Review" button (POST /{cr_id}/submit)
  - Under Review: "Approve" and "Reject" buttons (same as ApprovalQueue)
  - Approved: "Start Implementation" (POST /{cr_id}/transition with new_status="In Progress")
  - Staging: "Deploy to Production" (POST /{cr_id}/transition with new_status="Production") -- prominent warning that this requires manual CI/CD trigger
  - Production: "Mark Verified" (POST /{cr_id}/transition with new_status="Verified")
  - Verified: "Close" (POST /{cr_id}/transition with new_status="Closed")
  - Production/Verified: "Rollback" button (POST /{cr_id}/rollback) -- creates new CR

- **Audit Timeline** at bottom: Ant Design Timeline component showing all audit_entries for this CR. Each entry shows: action icon (GitBranch for pr_created, CheckCircle for approval, XCircle for rejection, Clock for status_change, Rocket for deployed), actor email, action description, timestamp (relative via date-fns formatDistanceToNow), metadata details expandable.
