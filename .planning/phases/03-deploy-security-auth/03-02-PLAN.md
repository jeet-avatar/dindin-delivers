Deploy the same security auth code (already verified on staging) to the production ECS service.

**Use the same ECR image from staging** if it was built from the same git commit. Otherwise, rebuild:

1. Authenticate to ECR:
```bash
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 134607809447.dkr.ecr.us-east-1.amazonaws.com
```

2. Tag the staging image for production (or rebuild if needed):
```bash
# Option A: Re-tag the staging-verified image
# Pull the staging image manifest and re-tag
STAGING_IMAGE="134607809447.dkr.ecr.us-east-1.amazonaws.com/dollor-api:security-auth-staging"
PROD_TAG="134607809447.dkr.ecr.us-east-1.amazonaws.com/dollor-api:security-auth-prod"
LATEST_TAG="134607809447.dkr.ecr.us-east-1.amazonaws.com/dollor-api:latest"

# Get staging image manifest and re-tag
MANIFEST=$(aws ecr batch-get-image --repository-name dollor-api --image-ids imageTag=security-auth-staging --query 'images[0].imageManifest' --output text)
aws ecr put-image --repository-name dollor-api --image-tag security-auth-prod --image-manifest "$MANIFEST" 2>/dev/null || true

# Option B: If re-tagging fails, rebuild from same commit
cd /Users/jeet/doordash-p2p/apps/web/p2p-platform/backend
docker build --no-cache --target production -f Dockerfile.optimized --platform linux/amd64 -t "$PROD_TAG" -t "$LATEST_TAG" .
docker push "$PROD_TAG"
docker push "$LATEST_TAG"
```

3. Record the CURRENT production task-def revision for rollback:
```bash
CURRENT_PROD_REV=$(aws ecs describe-task-definition --task-definition dollor-api --query 'taskDefinition.revision' --output text)
echo "ROLLBACK REVISION: dollor-api:$CURRENT_PROD_REV"
```

4. Download current production task-def, update image, register new revision:
```bash
aws ecs describe-task-definition --task-definition dollor-api --query 'taskDefinition' > /tmp/prod-task-def.json
jq 'del(.taskDefinitionArn, .revision, .status, .requiresAttributes, .compatibilities, .registeredAt, .registeredBy)' /tmp/prod-task-def.json > /tmp/clean-prod-task-def.json
jq '.containerDefinitions[0].image = "134607809447.dkr.ecr.us-east-1.amazonaws.com/dollor-api:security-auth-prod"' /tmp/clean-prod-task-def.json > /tmp/new-prod-task-def.json
aws ecs register-task-definition --cli-input-json file:///tmp/new-prod-task-def.json
```

5. Update the production ECS service:
```bash
NEW_PROD_ARN=$(aws ecs describe-task-definition --task-definition dollor-api --query 'taskDefinition.taskDefinitionArn' --output text)
aws ecs update-service --cluster dollor-production --service dollor-api-service --task-definition "$NEW_PROD_ARN" --force-new-deployment
```

6. Wait for service stability (production has 2 tasks, rolling deployment):
```bash
aws ecs wait services-stable --cluster dollor-production --services dollor-api-service
```

7. Verify both tasks are HEALTHY:
```bash
aws ecs describe-services --cluster dollor-production --services dollor-api-service --query 'services[0].{running: runningCount, desired: desiredCount, deployments: deployments[0].{status: status, running: runningCount, desired: desiredCount}}'
```

  <action>
Run the same smoke tests as staging against production, plus monitor CloudWatch for regressions.

**A. Production smoke test — public endpoints:**
```bash

curl -s -w '\n%{http_code}' https://api.dollor.ai/docs
```
Expected: All return non-401 status codes.

**B. Production smoke test — protected endpoints:**
```bash
curl -s -w '\n%{http_code}' https://api.dollor.ai/api/erp/orders/pending-restaurant
curl -s -w '\n%{http_code}' -X POST https://api.dollor.ai/api/stripe/create-payment-intent -H 'Content-Type: application/json' -d '{}'
curl -s -w '\n%{http_code}' https://api.dollor.ai/api/erp/customers/1/addresses
curl -s -w '\n%{http_code}' -X POST https://api.dollor.ai/api/erp/drivers/1/location -H 'Content-Type: application/json' -d '{"latitude":0,"longitude":0}'
```
Expected: All return 401 or 403.

**C. Authenticated flow with production demo account:**
```bash
RESPONSE=$(curl -s -X POST https://api.dollor.ai/api/auth/customer/login -H 'Content-Type: application/json' -d '{"email":"demo.customer@dollor.ai","password":"DemoCustomer2025!"}')
TOKEN=$(echo "$RESPONSE" | jq -r '.access_token // .token // empty')
if [ -n "$TOKEN" ]; then
  curl -s -w '\n%{http_code}' -H "Authorization: Bearer $TOKEN" https://api.dollor.ai/api/customer/profile
fi
```
Expected: Login succeeds, profile returns 200.

**D. CloudWatch monitoring (check for 401 spike):**
```bash
# Check ALB 4xx count for the last 10 minutes
aws cloudwatch get-metric-statistics \
  --namespace AWS/ApplicationELB \
  --metric-name HTTPCode_Target_4XX_Count \
  --dimensions Name=LoadBalancer,Value=$(aws elbv2 describe-load-balancers --query 'LoadBalancers[?contains(LoadBalancerName, `dollor`)].LoadBalancerArn' --output text | sed 's|.*loadbalancer/||') \
  --start-time $(date -u -v-10M +%Y-%m-%dT%H:%M:%SZ 2>/dev/null || date -u -d '10 minutes ago' +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 60 \
  --statistics Sum

# Also check ECS service events for any issues
aws ecs describe-services --cluster dollor-production --services dollor-api-service --query 'services[0].events[:5]'
```

If 4xx rate is significantly higher than pre-deployment baseline, this indicates legitimate app requests are being blocked. In that case, inform the user and prepare to rollback.
