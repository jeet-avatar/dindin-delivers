# Phase 08.1 Plan 02: Payment Capture Failure Recovery Summary

**One-liner:** Silent Stripe capture failures in complete_ride() replaced with explicit `capture_failed` flag + background retry job (every 5 min, 3 attempts max) with driver payout guard.

## What Was Built

Before this plan, if Stripe `PaymentIntent.capture` failed during `complete_ride()`, the exception was silently swallowed — `payment_status` stayed `None` forever, the driver payout was still attempted (which would fail since the charge source didn't succeed), and nobody knew the payment failed.

This plan adds three interlocking fixes:

### 1. `payment_retry_count` column on RideRequest (models.py + Alembic)

New `Integer` column with `default=0` added to the Payment block at `models.py:1381`. Alembic migration `20260318_add_payment_retry_count_ride_requests.py` adds it as `nullable=True` (existing rows treated as 0 via `or 0` guard in application logic).

### 2. Explicit `capture_failed` flag in complete_ride() (bid_routes.py)

The capture `except` block at `bid_routes.py:2380-2388` now:
- Sets `ride_request.payment_status = "capture_failed"`
- Increments `ride_request.payment_retry_count = (existing or 0) + 1`
- Commits to DB (with inner try/except to guard against DB write failure)

The driver payout block at `bid_routes.py:2390-2455` is now wrapped in an `if/else`:
- `if payment_status == "capture_failed"` → logs a warning, skips payout
- `else` → runs the existing payout logic unchanged

### 3. `check_capture_retry_job()` + scheduler registration (bid_routes.py + order_flow.py)

New function at `bid_routes.py:3809` retries failed captures:
- Queries COMPLETED rides in last 48 hours with `payment_status IS NULL OR payment_status = "capture_failed"` AND `stripe_payment_intent_id IS NOT NULL`
- Skips demo rides (`demo_` prefix)
- Skips rides where `payment_retry_count >= MAX_RETRIES (3)` — marks them `capture_failed` and logs for manual review
- On success: sets `payment_status = "captured"`, records `payment_completed_at`, increments counter
- On failure: increments counter, keeps `capture_failed` status
- Uses idempotency key `ride-capture-{ride_id}` matching the original capture attempt

Registered in `order_flow.py:start_timeout_scheduler()` at lines 2962-2967:
```python
restaurant_timeout_scheduler.add_job(
    check_capture_retry_job,
    IntervalTrigger(seconds=300),
    id="ride_capture_retry",
    name="Retry failed Stripe payment captures",
    replace_existing=True
)
```
