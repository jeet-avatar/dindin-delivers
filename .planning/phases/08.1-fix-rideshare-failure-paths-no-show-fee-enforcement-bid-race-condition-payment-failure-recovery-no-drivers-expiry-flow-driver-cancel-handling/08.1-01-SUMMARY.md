# Phase 08.1 Plan 01: No-Show Fee Enforcement Summary

**Stripe no-show enforcement in mark_passenger_no_show(): cancel pre-auth, charge $5.00 off-session from saved default card, transfer $4.00 to driver via Stripe Connect**

## Accomplishments
- Stripe no-show fee block inserted in `mark_passenger_no_show()` after the DB commit at line 2096
- Pre-auth PaymentIntent cancelled via `stripe.PaymentIntent.cancel()` with idempotency key `ride-noshow-cancel-{id}` before creating the $5 fee charge
- $5.00 off-session charge created via `stripe.PaymentIntent.create(confirm=True, off_session=True)` with `payment_method=default_pm_id` resolved from `customer.saved_cards` (is_default=True entry)
- $4.00 driver compensation transferred via `stripe.Transfer.create()` to `driver.stripe_account_id` with idempotency key `ride-noshow-xfer-{id}`
- Full graceful degradation: `payment_status=manual_review` set when no Stripe customer ID, no default card, CardError, or InvalidRequestError — the no-show DB record is never blocked

## Decisions Made
- Entire Stripe block is wrapped in outer `try/except Exception` — the DB no-show is always committed at line 2096 first; Stripe is best-effort
- `payment_method=default_pm_id` is resolved from `customer.saved_cards` JSON array (find entry with `is_default=True`, use its `'id'` field) — this is the critical fix that enables `confirm=True` off-session charging
- `CardError` and `InvalidRequestError` are caught specifically inside the charge attempt to set `payment_status="manual_review"` — no exception propagates up
- Inner try/except on the pre-auth cancel allows the flow to continue even if the original PI is already cancelled or in an uncancellable state
