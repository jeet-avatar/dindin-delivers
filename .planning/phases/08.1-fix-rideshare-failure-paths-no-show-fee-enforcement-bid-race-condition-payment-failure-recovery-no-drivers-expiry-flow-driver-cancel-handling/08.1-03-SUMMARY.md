# Phase 08.1 Plan 03: No-Drivers Expiry Flow — iOS Customer Banner Summary

**One-liner:** Wired `RideRequestExpired` NotificationCenter event (posted by App.swift push handler) to a sliding orange banner in RideRequestView with a "Try Again" button that resets the booking form.

## What Was Built

The backend scheduler already expires rides when no driver accepts within the bidding window and sends a `ride_expired` push. The push handler in `eatfaircustomerApp.swift:202` was already posting a `RideRequestExpired` NotificationCenter event — but nothing in the app was listening to it. Customers tapped the push notification and saw a blank/unchanged screen with no call to action.

This plan wired the missing link: `RideRequestView.swift` now observes `RideRequestExpired` and shows a visible banner.

## Changes Made

### `apps/ios/customer/eatfaircustomer/Views/RideRequestView.swift`

**3 additive changes (no existing logic modified):**

1. **`@State private var showRideExpiredBanner: Bool = false`** (line 22) — new state variable

2. **Banner block inside ZStack** (lines 72-109) — conditional `VStack` with:
   - `clock.badge.exclamationmark` icon in orange
   - "No drivers available" title + "No drivers accepted your request. Try again?" subtitle
   - "Try Again" orange button: dismisses banner + calls `viewModel.resetRide()`
   - Slide-in transition from top with spring animation
   - `zIndex(100)` to render above fare/loading overlays
   - 10-second auto-dismiss timer

3. **`.onReceive` modifier** (lines 152-162) — listens to `NSNotification.Name("RideRequestExpired")`, sets `showRideExpiredBanner = true` with animation, schedules auto-dismiss after 10s
