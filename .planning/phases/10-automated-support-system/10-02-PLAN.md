  <action>
    **voice_agent.py** -- Twilio Media Streams to OpenAI Realtime API bridge.

    Follow the official Twilio + OpenAI Python tutorial pattern (referenced in 10-RESEARCH.md Pattern 1 and Pattern 2). Create a FastAPI APIRouter with prefix "" (endpoints mounted at app level).

    1. **Constants and config:**
       - `OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")`
       - `VOICE = "sage"` (per research recommendation -- calm, professional support tone)
       - `OPENAI_REALTIME_URL = "wss://api.openai.com/v1/realtime?model=gpt-realtime"`
       - `MAX_CALL_DURATION_MINUTES = 10` (Claude's discretion -- leaves 5 min buffer before 15-min API limit)
       - Module-level logger: `logger = logging.getLogger(__name__)`

    2. **System prompt** (`SUPPORT_AGENT_SYSTEM_PROMPT`):
       - Identity: "You are Dollor AI Support, an AI assistant for Dollor.ai -- a matchmaking platform connecting customers with drivers for food delivery and rideshare."
       - Transparent: "You are an AI assistant, not a human. Be upfront about this."
       - Capabilities: Look up orders, look up rides, check account status, log escalation requests
       - Limitations: Cannot process refunds directly (log for human follow-up), cannot modify orders or rides
       - Tone: Patient, professional, empathetic. Handle frustrated callers calmly.
       - User routing: "The caller's phone number will be matched to their account. Use it to identify their role (customer, driver, or restaurant owner)."
       - Time awareness: "Keep conversations focused. After 8 minutes, suggest the caller email support@dollor.ai for complex issues."
       - Business context: Include key pricing info -- customers pay $1 service fee, drivers keep 100% of delivery fees + tips, rideshare has $1/$2/$3 tiered platform fee

    3. **Endpoint: `/api/voice/incoming-call`** (GET and POST):
       - Returns TwiML XML via `twilio.twiml.voice_response.VoiceResponse`
       - Greeting: `response.say("This call may be recorded for quality purposes.")` then `response.pause(length=1)`
       - Then: `Connect` with `Stream` pointing to `wss://{host}/api/voice/media-stream`
       - Pass caller phone number as custom parameter in the Stream URL: `?caller={request.query_params.get('From', '')}`
       - Return as `HTMLResponse` with `media_type="application/xml"`

    4. **WebSocket endpoint: `/api/voice/media-stream`** (WebSocket):
       - Accept the WebSocket connection
       - Extract `caller` phone from query params
       - Connect to OpenAI Realtime API via `websockets.connect()` with auth headers:
         ```
         Authorization: Bearer {OPENAI_API_KEY}
         OpenAI-Beta: realtime=v1
         ```
       - Call `initialize_session(openai_ws, caller_phone)` to send session.update with tools, system prompt, and audio format config
       - Audio format: Set both input and output to `audio/pcmu` (mu-law) -- this matches Twilio's native format, NO transcoding needed
       - Enable input audio transcription: `{"model": "whisper-1"}`
       - Turn detection: `{"type": "server_vad"}` (server-side voice activity detection)
       - Run two async tasks concurrently (`asyncio.gather`):
         a. `receive_from_twilio()`: Read Twilio WS messages, forward `media` events as `input_audio_buffer.append` to OpenAI
         b. `send_to_twilio()`: Read OpenAI WS messages, forward `response.audio.delta` events back to Twilio as media payloads
       - In `send_to_twilio()`, also handle:
         - `response.function_call_arguments.done` events: Execute tool via `voice_agent_tools.execute_tool()`, send result back to OpenAI as `conversation.item.create` with role=tool
         - `error` events: Log the error
         - `session.created` / `session.updated`: Log for debugging
       - Wrap the entire function in try/except/finally to ensure both WebSocket connections are properly closed
       - Track `stream_sid` from Twilio's `start` event (needed for sending media back)

    5. **Helper: `initialize_session(openai_ws, caller_phone)`:**
       - Look up caller by phone number in the database to determine role (customer/driver/vendor)
       - Inject caller context into system prompt: "The caller is {name}, a {role} with phone {phone}."
       - Send `session.update` with tools, system prompt, voice, audio format, turn detection

    6. **Add these endpoints to the router to be exempt from auth middleware:**
       - `/api/voice/incoming-call` must be in the auth middleware allowlist (Twilio webhook, no JWT)
       - `/api/voice/media-stream` is a WebSocket endpoint (auth not applicable for WS)

    **voice_agent_tools.py** -- Tool implementations for the AI agent.

    1. **`execute_tool(tool_name: str, arguments: dict, db: Session) -> str`:**
       - Dispatch to the correct tool function by name
       - Return JSON string result for OpenAI

    2. **`lookup_order(arguments: dict, db: Session) -> str`:**
       - Accept `order_id` (int) or `phone` (str)
       - If `order_id`: Query Order table directly
       - If `phone`: Find customer by phone → find their recent orders (last 5)
       - Return JSON with: order_id, status, restaurant_name, total, created_at, driver_name (if assigned)
       - If not found: return `{"error": "No orders found"}`

    3. **`lookup_ride(arguments: dict, db: Session) -> str`:**
       - Accept `ride_id` (int) or `phone` (str)
       - If `ride_id`: Query RideRequest table directly
       - If `phone`: Find customer by phone → find their recent rides (last 5)
       - Return JSON with: ride_id, status, pickup, dropoff, fare, driver_name (if matched)
       - If not found: return `{"error": "No rides found"}`

    4. **`log_escalation(arguments: dict, db: Session) -> str`:**
       - Accept `caller_phone`, `issue_type` (enum: refund, complaint, account_issue, other), `summary`
       - Send email to support@dollor.ai via the existing `email_service.send_email()` function
       - Email subject: `"[Escalation] {issue_type} from {caller_phone}"`
       - Email body: Summary + caller details + timestamp
       - Return `{"success": true, "message": "Escalation logged. A team member will follow up."}`

    5. **`lookup_account(arguments: dict, db: Session) -> str`:**
       - Accept `phone` (str)
       - Search across Customer, Driver, Vendor tables by phone number
       - Return JSON with: name, role, email, account status (is_active for customers, driver_status for drivers, status for vendors)
       - This helps the AI agent identify who is calling and route appropriately

    Import models from `models.py` (Customer, Driver, Vendor, Order, RideRequest) and `database.py` (get_db).
    Import `email_service` for escalation emails.
    Follow existing backend conventions: snake_case functions, logger per module, HTTPException for errors.
