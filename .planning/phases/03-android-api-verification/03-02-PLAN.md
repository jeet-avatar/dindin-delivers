Check for edge cases specific to the Driver app:

1. **DocumentsViewModel direct API calls**: This ViewModel uses `DollorApiService` directly (not via DollorRepository). Verify:
   - `apiService.getDriverDocuments(driverId, authToken)` maps to `GET drivers/{driverId}/documents`
   - `apiService.uploadDriverDocument(driverId, file, documentType, authToken)` maps to `POST drivers/{driverId}/documents`
   Verify backend has these routes with multipart support for uploads.

2. **Auth header patterns**: Check that the Driver app passes auth tokens correctly. The DollorApiService uses `@Header("Authorization") token: String` pattern. Verify that driver ViewModels call with `secureStorage.getAuthHeader(SecureStorage.UserType.DRIVER)` format (which produces "Bearer {token}").
   ```bash
   grep -n "getAuthHeader\|authToken\|bearerToken\|Authorization" /Users/jeet/StudioProjects/eatfair-android/driver/src/main/java/ai/dollor/driver/ui/*/*.kt
   ```

3. **Known previous issues**: The iOS verification (Phase 02) found a broken doc upload alias and wrong chat auth token in the driver app. Check if the same issues exist on Android:
   - Driver document upload: Does Android use the correct multipart endpoint?
   - Ride chat: Does Android use the correct chat endpoint path (`p2p/ride-requests/{id}/chat`)?
   - FCM token: Does Android use POST (not PUT) for `notifications/register-token`?

5. **Pending orders endpoint**: Check `GET erp/orders/driver/{driverId}/pending` and `PUT erp/orders/{orderId}/unassign-driver` exist in backend.
