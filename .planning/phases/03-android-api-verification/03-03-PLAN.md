**Step 3: Check partner-specific edge cases:**

1. **RestaurantDocumentsViewModel**: Uses `api.getVendorDocuments()` and `api.uploadVendorDocument()` directly. Verify multipart upload support matches backend.

2. **Multiple PATCH overloads**: DollorApiService has 4 different `@PATCH("vendors/{vendorId}")` methods with different request body types. Verify backend handles all body shapes on the same route.

3. **Order status updates**: 4 different status update methods all hit `PATCH orders/{orderId}/status` with different body shapes. Verify backend accepts all status values.

4. **Registration flow**: `RegistrationViewModel` may call both `vendorRegister` and `registerPublicVendor`. Verify both backend routes exist and differ correctly:

   - `POST vendors/public` = public self-registration
