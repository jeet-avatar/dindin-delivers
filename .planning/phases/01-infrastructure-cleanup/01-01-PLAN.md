<task type="auto">
  <name>Task 1: Create and attach CloudFront response headers policy to production and staging distributions</name>
  <files>No repo files modified — AWS infrastructure only</files>
  <action>
    Create a CloudFront response headers policy via AWS CLI that:
    1. Sets `Server` header override to `Dollor` (removes uvicorn exposure)
    2. Adds security headers:
       - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (HSTS)
       - `X-Content-Type-Options: nosniff`
       - `X-Frame-Options: DENY`
       - `Referrer-Policy: strict-origin-when-cross-origin`

    Steps:
    a. Look up the production API CloudFront distribution ID:
       `aws cloudfront list-distributions --query "DistributionList.Items[?contains(Aliases.Items, 'api.dollor.ai')].Id" --output text`
       (If no alias match, use the distribution whose domain is `d3kuu45w6kl8hr.cloudfront.net`)

    b. Create response headers policy:
       ```
       aws cloudfront create-response-headers-policy --response-headers-policy-config '{
         "Name": "dollor-security-headers",
         "Comment": "Suppress uvicorn server header, add security headers",
         "SecurityHeadersConfig": {
           "StrictTransportSecurity": {
             "Override": true,
             "AccessControlMaxAgeSec": 31536000,
             "IncludeSubdomains": true,
             "Preload": false
           },
           "ContentTypeOptions": {
             "Override": true
           },
           "FrameOptions": {
             "Override": true,
             "FrameOption": "DENY"
           },
           "ReferrerPolicy": {
             "Override": true,
             "ReferrerPolicy": "strict-origin-when-cross-origin"
           }
         },
         "ServerTimingHeadersConfig": {
           "Enabled": false
         },
         "CustomHeadersConfig": {
           "Quantity": 1,
           "Items": [
             {
               "Header": "Server",
               "Value": "Dollor",
               "Override": true
             }
           ]
         }
       }'
       ```
       Save the returned policy ID.

    c. Attach policy to production API distribution:
       - Get current distribution config: `aws cloudfront get-distribution-config --id <PROD_DIST_ID>`
       - Save the ETag from the response
       - Update the default cache behavior to include `ResponseHeadersPolicyId: <POLICY_ID>`
       - Update distribution: `aws cloudfront update-distribution --id <PROD_DIST_ID> --if-match <ETAG> --distribution-config <UPDATED_CONFIG>`

    d. Attach same policy to staging distribution (E3LB9SMG1YD9ZL):
       - Same get-config → update-config process with the staging distribution ID

    e. Wait for both distributions to deploy (status: Deployed):
       `aws cloudfront wait distribution-deployed --id <DIST_ID>` (run for each)

    IMPORTANT: Do NOT modify any other distribution settings. Only add the ResponseHeadersPolicyId to the existing default cache behavior config. Preserve all existing settings (origins, behaviors, etc.) exactly as they are.

    If AWS CLI auth fails, create a checkpoint:human-action for user to authenticate.
  </action>
  <verify>
    Run these curl commands and verify headers:
    ```
    curl -sI https://api.dollor.ai/health | grep -iE "^(server|strict-transport|x-content-type|x-frame|referrer-policy):"
    curl -sI https://d34u5ixl0bulv4.cloudfront.net/health | grep -iE "^(server|strict-transport|x-content-type|x-frame|referrer-policy):"
    ```
    Expected: `Server: Dollor`, plus all 4 security headers on both URLs.
    The `Server` header must NOT contain `uvicorn`.
  </verify>
