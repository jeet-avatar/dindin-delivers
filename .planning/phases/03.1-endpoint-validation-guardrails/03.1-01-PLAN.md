Create a Python script at `scripts/extract-api-endpoints.py` that extracts all FastAPI route definitions from the backend codebase and outputs a canonical endpoint registry.

**Script requirements:**

1. **Input:** Scan all `.py` files in `apps/web/p2p-platform/backend/` recursively
2. **Pattern matching:** Extract routes from two decorator patterns:
   - `@app.(get|post|put|delete|patch)("/path/here"...)` (main_new.py uses `app` directly)
   - `@router.(get|post|put|delete|patch)("/path/here"...)` (other files use APIRouter)
3. **For each route, extract:**
   - HTTP method (GET, POST, PUT, DELETE, PATCH)
   - Path (the first string argument to the decorator)
   - Source file and line number
   - Auth status: Check if the function has `Depends(require_any_auth)`, `Depends(require_customer)`, `Depends(require_driver)`, `Depends(require_vendor)`, or `Depends(require_admin)` in its signature. Also check if path is in `_PUBLIC_EXACT_PATHS` or matches `_PUBLIC_PATH_PREFIXES`/`_PUBLIC_PATH_PATTERNS` from main_new.py. Label as "public", "auth-required", or "admin-only".
4. **Output format:** Markdown table sorted by path, with columns: Method | Path | Auth | Source

**Script should:**
- Use only stdlib (re, os, pathlib, sys) -- no external dependencies
- Accept an optional `--output` flag to write to a file (default: stdout)
- Print a header with generation timestamp and total count
- Exit with code 0 on success

**After creating the script, run it:**
```bash
cd /Users/jeet/doordash-p2p
python scripts/extract-api-endpoints.py --output .planning/API_REGISTRY.md
```

**Verify the output contains known endpoints:**
- `/api/vendors/published` should be listed as GET, public
- `/api/promotions/featured` should be listed as GET, public
- `/api/vendors/featured` should NOT appear (confirming it was never a real route)
- `/api/customer/profile` should be listed as GET, auth-required
- Total count should be in the range of 500-800 (there are ~699 route decorators across 16 files)

The script does NOT need to be perfect -- it is a grep+regex tool, not an AST parser. Edge cases (computed routes, include_router prefixes) can be documented as known limitations in a comment at the top.

**Known complexity:** Files using `APIRouter` have a `prefix=` argument on the router, and the routes are relative. The script should attempt to resolve the full path by checking for `app.include_router(router, prefix="/api/...")` calls in main_new.py. If prefix resolution is too complex, output the relative path with a note.
