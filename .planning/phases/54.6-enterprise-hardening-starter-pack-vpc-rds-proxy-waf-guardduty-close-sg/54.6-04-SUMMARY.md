## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] AWS CLI `--cli-binary-format` flag rejected**
- **Found during:** Task 2 first smoke run.
- **Issue:** Plan's smoke script called `aws lambda invoke --cli-binary-format raw-in-base64-out` directly. Operator's AWS CLI version returned `Unknown options: --cli-binary-format`.
- **Fix:** Rewrote Task 2 step [1] to use `curl` against each Lambda's APIGW HTTP endpoint instead of `aws lambda invoke`. This matches the 54.6-02 smoke pattern that worked end-to-end. HTTP-via-APIGW also proves the full Lambda→Proxy→Aurora chain (returns real DB query result `db=ok` or `database=connected`).
- **Files modified:** `scripts/smoke-phase-54-6.sh`
- **Commit:** `be225789`

**2. [Rule 1 - Bug] `wafv2 list-resources-for-web-acl --resource-type CLOUDFRONT` not supported**
- **Found during:** Task 2 first smoke run.
- **Issue:** Plan's smoke script called `aws wafv2 list-resources-for-web-acl --web-acl-arn ... --resource-type CLOUDFRONT` which returned `ValidationException: Value 'CLOUDFRONT' at 'resourceType' failed to satisfy constraint: Member must satisfy enum value set: [APPLICATION_LOAD_BALANCER, COGNITO_USER_POOL, APP_RUNNER_SERVICE, AMPLIFY, VERIFIED_ACCESS_INSTANCE, APPSYNC, API_GATEWAY]`.
- **Root cause:** `list-resources-for-web-acl` is REGIONAL-scope only. CloudFront attachment is verified via the CloudFront side, not WAFv2 side. Consistent with 54.6-03 finding that CF attach uses `cloudfront update-distribution` not `wafv2 associate-web-acl`.
- **Fix:** Rewrote Task 2 step [10] to iterate the 2 known CF distro IDs (E37R9PT8IL44L2, E1X82T89JWL8CA) and call `cloudfront get-distribution-config --query DistributionConfig.WebACLId`. Compares each WebACLId to the WAF ACL ARN; passes if ≥2 distros are attached.
- **Files modified:** `scripts/smoke-phase-54-6.sh`
- **Commit:** `be225789`

**3. [Rule 3 - Blocking] `grep -c` returns multi-line "0\n0" tripping integer comparison**
- **Found during:** Task 2 second smoke run (cosmetic warning).
- **Issue:** Inline `HAS_CF=$(echo "$HEAD" | grep -ci ... || echo 0)` produced output like `0\n0` (grep returned 0 + fallback `echo 0`), tripping `[: 0\n0: integer expression expected`. Functionally harmless (probes still passed), but emitted bash warnings.
- **Fix:** Replaced with `HAS_CF=$(echo "$HEAD" | grep -c '^x-amz-cf-id:' 2>/dev/null | head -1); HAS_CF=${HAS_CF:-0}` — `head -1` collapses to single line; parameter-expansion default catches empty.
- **Files modified:** `scripts/smoke-phase-54-6.sh`
- **Commit:** Folded into `be225789` (one commit for the whole script after iteration).
