**Step 3: For EACH function that constructs a URL, verify:**
1. **URL path**: Does the exact path exist as a backend route? Use `grep -rn "path/segment" apps/web/p2p-platform/backend/*.py` to confirm
2. **HTTP method**: Does the iOS code use the same method (GET/POST/PUT/DELETE/PATCH) as the backend route?
3. **Auth header**: Does the iOS code send the correct auth token (customer/driver/vendor)? Cross-check backend uses `Depends(require_customer)` or appropriate auth
4. **Request body**: Do the JSON keys in the iOS request body match the backend's expected parameter names?
5. **Response model**: Do the iOS response model field names and types match what the backend returns?
6. **Content-Type**: Is the Content-Type header correct (application/json for most, multipart/form-data for uploads)?

**Step 4: Identify which P2PAPIService functions are Customer-specific**
P2PAPIService has functions for ALL roles (customer, driver, vendor). Focus on:
- Functions called from `apps/ios/customer/` source files (grep for function names)
- Functions in MARK sections labeled "Customer" or "Public"
- Auth functions used by the customer app (customer login, register, etc.)
- Restaurant/menu browsing functions (public endpoints)
- Order functions (customer ordering flow)
- Rideshare functions called from customer ViewModels
- Address/profile functions for customers
- Payment/card functions for customers
