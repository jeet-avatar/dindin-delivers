<objective>
Build and deploy 4 Cognito-trigger Lambda functions in Node.js 20.x:
1. **Custom Email Sender** — receives Cognito's KMS-encrypted code, decrypts via `@aws-crypto/client-node`, sends a branded HTML email via SES v2 for built-in flows (AdminCreateUser invite suppressed in our migration, but covers ForgotPassword + any other built-in code paths).
2. **Define Auth Challenge** — state machine: first call → issue CUSTOM_CHALLENGE; second call (after verify succeeds) → issue tokens.
3. **Create Auth Challenge** — generates a high-entropy nonce, sends a magic-link URL via SES v2, stashes nonce in `privateChallengeParameters`.
4. **Verify Auth Challenge Response** — compares user-supplied answer to stashed nonce.

Plus: a new IAM role `zietra-cognito-email-sender-role` granting `ses:SendEmail` on `zietra.com`, `kms:Decrypt` on the Cognito CMK, and CloudWatch logs basic execution. After all 4 Lambdas exist and IAM permissions for `cognito-idp.amazonaws.com` to `lambda:InvokeFunction` are granted, wire them into the user pool via `aws cognito-idp update-user-pool --lambda-config`.

Purpose: This plan is parallel-safe with 39-01 because it shares no AWS resource UP UNTIL the final `update-user-pool` wiring step. The wiring step's prerequisites — pool ID + KMS key ARN — are read from `zietra/cognito-config` Secrets Manager (populated by 39-01). The script polls Secrets Manager until populated and waits if needed.

Output: 4 Lambda functions deployed, role with policies attached, Cognito wired to them.
</objective>

```typescript
import { KmsKeyringNode, buildClient, CommitmentPolicy } from '@aws-crypto/client-node';
import { sendBrandedEmail } from './ses.js';
import fs from 'node:fs/promises';
import path from 'node:path';

const { decrypt } = buildClient(CommitmentPolicy.REQUIRE_ENCRYPT_ALLOW_DECRYPT);
const KEY_ARN = process.env.KMS_KEY_ARN;
if (!KEY_ARN) throw new Error('KMS_KEY_ARN env var required');
const keyring = new KmsKeyringNode({ generatorKeyId: KEY_ARN, keyIds: [KEY_ARN] });

// Cache templates at cold start
const TEMPLATES: Record<string, string> = {};
async function loadTemplate(name: string): Promise<string> {
  if (!TEMPLATES[name]) {
    TEMPLATES[name] = await fs.readFile(path.join(__dirname, 'templates', `${name}.html`), 'utf-8');
  }
  return TEMPLATES[name];
}

function unescapeHtml(s: string): string {
  return s.replace(/&lt;/g, '<').replace(/&gt;/g, '>').replace(/&amp;/g, '&');
}

export const handler = async (event: any) => {
  console.log('[ces] triggerSource:', event.triggerSource);
  if (!event.request.code) {
    console.log('[ces] no code in event — skipping');
    return event;
  }
  const { plaintext } = await decrypt(keyring, Buffer.from(event.request.code, 'base64'));
  let code = Buffer.from(plaintext).toString('utf-8');

  // Per Cognito docs: AdminCreateUser temp passwords are HTML-escaped before encryption
  if (event.triggerSource === 'CustomEmailSender_AdminCreateUser') {
    code = unescapeHtml(code);
  }

  const email: string = event.request.userAttributes.email;
  const trigger: string = event.triggerSource;

  // Map trigger source → template name + subject
  const triggerMap: Record<string, { tpl: string; subject: string }> = {
    'CustomEmailSender_SignUp':           { tpl: 'admin-create-user', subject: 'Verify your Zietra email' },
    'CustomEmailSender_AdminCreateUser':  { tpl: 'admin-create-user', subject: 'Welcome to Zietra' },
    'CustomEmailSender_ResendCode':       { tpl: 'admin-create-user', subject: 'Your Zietra verification code' },
    'CustomEmailSender_ForgotPassword':   { tpl: 'forgot-password',   subject: 'Reset your Zietra password' },
    'CustomEmailSender_UpdateUserAttribute': { tpl: 'admin-create-user', subject: 'Confirm your Zietra email' },
    'CustomEmailSender_VerifyUserAttribute': { tpl: 'admin-create-user', subject: 'Confirm your Zietra email' },
    'CustomEmailSender_AccountTakeOverNotification': { tpl: 'admin-create-user', subject: 'Zietra security notice' },
  };
  const cfg = triggerMap[trigger] ?? { tpl: 'admin-create-user', subject: 'Zietra notification' };
  let html = await loadTemplate(cfg.tpl);
  html = html.replace(/\{\{CODE\}\}/g, code).replace(/\{\{EMAIL\}\}/g, email);

  await sendBrandedEmail({ to: email, subject: cfg.subject, html });
  console.log('[ces] sent to', email, '·', cfg.tpl);
  return event;
};
```

**`src/create-auth-challenge.ts`** — per 39-RESEARCH.md §"Lambda: create-auth-challenge.ts" but with template loading:
```typescript
import crypto from 'node:crypto';
import { sendBrandedEmail } from './ses.js';
import fs from 'node:fs/promises';
import path from 'node:path';

const BASE_URL = process.env.MAGIC_LINK_BASE_URL;
if (!BASE_URL) throw new Error('MAGIC_LINK_BASE_URL env var required');

let magicLinkTpl: string | null = null;
async function tpl(): Promise<string> {
  if (!magicLinkTpl) {
    magicLinkTpl = await fs.readFile(path.join(__dirname, 'templates', 'magic-link.html'), 'utf-8');
  }
  return magicLinkTpl;
}

export const handler = async (event: any) => {
  if (event.request.challengeName !== 'CUSTOM_CHALLENGE') return event;
  if (event.request.session && event.request.session.length !== 0) return event;

  const nonce = crypto.randomBytes(32).toString('base64url');
  const email: string = event.request.userAttributes.email;
  const url = `${BASE_URL}/cognito-auth-callback?token=${nonce}&email=${encodeURIComponent(email)}`;

  let html = await tpl();
  html = html.replace(/\{\{URL\}\}/g, url).replace(/\{\{EMAIL\}\}/g, email);
  await sendBrandedEmail({ to: email, subject: 'Sign in to Zietra', html });
  console.log('[create-auth-challenge] magic-link sent to', email);
  // For smoke-test purposes, also log the nonce so the operator can grab it from CloudWatch
  // without needing inbox access. Acceptable per Phase 39 scope (no end-user traffic yet).
  console.log('[create-auth-challenge] nonce=' + nonce);

  event.response.publicChallengeParameters = { email };
  event.response.privateChallengeParameters = { answer: nonce };
  event.response.challengeMetadata = 'MAGIC_LINK';
  return event;
};
```

      --runtime nodejs20.x --handler "$handler" --role "$ROLE_ARN" \

      --region "$REGION" >/dev/null

      --runtime nodejs20.x --handler "$handler" --role "$ROLE_ARN" \

      --environment "Variables={KMS_KEY_ARN=$KEY_ARN,MAGIC_LINK_BASE_URL=$MAGIC_LINK_BASE_URL}" \
      --region "$REGION" >/dev/null
    aws lambda wait function-active --function-name "$fn" --region "$REGION"
    echo "Created: $fn"
  fi
done

# === 4. Grant Cognito permission to invoke each Lambda ===
echo "=== 4. Cognito invoke permissions ==="
for fn in "${!FUNCTIONS[@]}"; do
  STMT_ID="cognito-invoke-${fn}"
  aws lambda remove-permission --function-name "$fn" --statement-id "$STMT_ID" --region "$REGION" 2>/dev/null || true
  aws lambda add-permission --function-name "$fn" \
    --statement-id "$STMT_ID" \
    --action lambda:InvokeFunction \
    --principal cognito-idp.amazonaws.com \
    --source-arn "arn:aws:cognito-idp:${REGION}:${ACCOUNT}:userpool/${POOL_ID}" \
    --region "$REGION" >/dev/null
  echo "Permission granted: cognito-idp.amazonaws.com → $fn"
done

echo "=== 5. UpdateUserPool — wire Lambda triggers + KMS key ==="

VERIFY_ARN=$(aws lambda get-function --function-name zietra-cognito-verify-auth-challenge --query 'Configuration.FunctionArn' --output text --region "$REGION")

aws cognito-idp update-user-pool --user-pool-id "$POOL_ID" --region "$REGION" \
  --lambda-config "{
    \"CustomEmailSender\": { \"LambdaVersion\": \"V1_0\", \"LambdaArn\": \"$CES_ARN\" },
    \"DefineAuthChallenge\": \"$DEFINE_ARN\",
    \"CreateAuthChallenge\": \"$CREATE_ARN\",
    \"VerifyAuthChallengeResponse\": \"$VERIFY_ARN\",

  }"

echo ""
