## Decisions Made

1. **AUTOGEN both `.ts` AND `.mjs`** from sync-modules.mjs — picked Step G option (a) from plan. The .ts file is consumed by the React app (typed, tree-shaken by Vite); the .mjs sibling lets gen-sitemap.mjs import the same data in pure Node without adding tsx/ts-node to the toolchain.
2. **Static lucide-react named-import map** instead of `import * as Icons from 'lucide-react'` — caught a 778 KB ModuleCard chunk after first build (Vite couldn't tree-shake the dynamic icon lookup). Replaced with an 11-icon named-import map keyed on the kebab-case `icon` field → bundle dropped to 7.8 KB (Rule 2 fix, perf).
3. **Strict 1:1 drift policy** — both missing-from-marketing AND extra-not-in-upstream throw + exit 1. Verified by negative test: added a fake slug to marketing-copy.mjs, build failed with explicit "STALE for codes not in upstream: fake-module-test" message, restored, build succeeded.
4. **No tabs / no useState on ModulePage** — 5 stacked sections per RESEARCH Pattern 1. Tabs hurt SEO (content hidden in inactive panels) and accessibility (keyboard nav, screen readers).
5. **Unknown slug → Navigate to /modules** (Pitfall 11) — `useParams<{slug: string}>()` + `MODULES.find(...)`, falsy → `<Navigate to="/modules" replace />`. User lands on the index with all 13 cards, not a 404.
6. **CTAs are cross-origin `<a href>`** not `<Link>` — `${APP_SIGNUP}?intent=${m.slug}` preserves intent through Cognito hosted UI handoff (Pattern 1 from 58-01).
7. **Lazy-load ModulePage + ModulesIndexPage** in App.tsx — keeps home bundle light. Module data chunk ships independently (24 KB / 8.7 KB gzip) and is only loaded when a user navigates to /modules or any /modules/:slug.
8. **`/llms.txt` + `/robots.txt` + `/sitemap.xml` invalidation** — deploy.sh defaults to invalidating only `/` + `/index.html`, but sitemap.xml changed structure (9 → 22 URLs) and is served with `immutable` cache-control. Issued explicit follow-up invalidation `ID9EX1DAPJCS8W6I1QQMYK0MIS` (Rule 3 auto-fix).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] ModuleCard bundle was 778 KB (entire lucide-react)**
- **Found during:** Task 2 (first `npm run build` run)
- **Issue:** Initial ModuleCard used `import * as Icons from 'lucide-react'` for runtime icon lookup. Vite couldn't tree-shake the dynamic property access, so all 1,500+ lucide icons got bundled → 778 KB chunk (a 500 KB chunk-size warning was emitted).
- **Fix:** Replaced with a static `ICON_MAP` of 11 named imports (the 10 icons actually used by the 13 modules + `Box` fallback). Bundle dropped 778 KB → 7.8 KB (100× reduction). Vite chunk-size warning gone.
- **Files modified:** `src/components/ModuleCard.tsx`
- **Verification:** `dist/assets/ModuleCard-*.js` size before fix: 777.77 KB / after fix: 7.81 KB
- **Committed in:** `f8e28c1` (single Task 2 commit — fix applied before the commit was made)

**2. [Rule 3 - Blocking] Sitemap on CloudFront still showed 9 URLs after deploy**
- **Found during:** Live smoke test (after first deploy + invalidation)
- **Issue:** `deploy.sh` only invalidates `/` + `/index.html`. The new 22-URL sitemap.xml was uploaded to S3 with `cache-control: public, max-age=31536000, immutable`, but CloudFront still served the cached 9-URL version from 58-01.
- **Fix:** Issued explicit second invalidation for `/sitemap.xml` + `/robots.txt` + `/llms.txt` (CloudFront invalidation ID `ID9EX1DAPJCS8W6I1QQMYK0MIS`).
- **Files modified:** None (operational fix only)
- **Verification:** Post-invalidation: `curl -s https://zietra.com/sitemap.xml | grep -c "<loc>"` → 22 (was 9)
- **Documented in:** `4645e28` (deploy marker commit body)
- **Out-of-scope follow-up logged:** Should update `deploy.sh` to invalidate `/sitemap.xml` + `/robots.txt` + `/llms.txt` by default — but that's a separate change to a shared script; logging for a future plan rather than slipping it in here.
