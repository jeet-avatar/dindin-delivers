# Phase 65.2 Plan 03: Data-aware onboarding wizard UI Summary

**Rewrote `/onboarding/recommend.html` (269 → 445 lines) so the wizard fetches `GET /api/onboarding/profile` on mount, renders question sets dynamically from the response, pre-checks prefilled answers, shows a "Why these picks?" data-signals strip with source badge, and debounce-autosaves every edit to `PATCH /api/onboarding/profile` — with a 404 fallback to the original hardcoded form for graceful pre-deploy degradation.**

## Accomplishments

1. **Dynamic question rendering** — all `<button data-value="...">` are now generated at runtime from `state.questionSet.questions`. Zero hardcoded option attributes in the static HTML body. The same renderer drives any of the 3 question sets shipped by Plan 01 (`d2c-multibrand`, `aerospace-hardware`, `services-saas`) plus the 404 fallback set.
2. **Prefilled answers visually selected on first paint** — `state.answers` (sourced from `response.prefilled_answers`) is checked against each option's value during render; selected options get the `.selected` class immediately. Multi-select (`tools_today`) checks via `Array.includes`; single-select via `===`.
3. **"Why these picks?" signals strip** at top of form — conditionally renders only when `state.signals` OR `state.corporateSummary` is present (Pitfall 4 guard). Shows: item count + brand count, sales-order count + dollar total, BOM parts, vendors, customers, and corporate facts (legal name + headcount + industry). Source badge swaps between purple "pre-filled" and green "you customized this" based on `state.source`.
4. **400ms debounced autosave** — `pendingPatch` setTimeout cancelled by `clearTimeout` on every new click (Pitfall 8). `pendingDiff` accumulator merges multiple edits within the window into ONE PATCH. After PATCH resolves, `state.source` flips to `'user'` and the signals strip re-renders.
5. **Recommend POST passes signals** — `Object.assign({}, state.answers, { data_signals: state.signals })` is the body, so Plan 02's rule engine scores against real introspected data (the Solo Brands 9-module match path).
6. **Finalize POST contract unchanged** — `{ selected_modules: [...] }` byte-equal to the pre-rewrite. Cached browsers running the old JS still finalize successfully because the route, payload shape, and response handling are all untouched.
7. **404 fallback for missing endpoint** — if `GET /api/onboarding/profile` returns 404 (no profile row OR Plan 02 not yet deployed), the page silently falls back to a `FALLBACK_QUESTION_SET` constant (the original 5-question form: industry/team_size/pain_point/tools_today/asc606_needs with the same options as the pre-rewrite HTML). Autosave is suppressed in fallback mode (`state.fallback === true`) to avoid 404 spam on every click. Show-modules + Finalize still work.

## Signals Strip Template (rendered HTML)

Format string (computed in `renderSignalsStrip()`):

```
💡 <strong>Why these picks?</strong> Based on <bits joined by ' · '><source-badge>
```

Each `bit` is conditional on its underlying signal being non-zero / non-null:

| Signal field             | Rendered bit (when present)                                              |
| ------------------------ | ------------------------------------------------------------------------ |
| `item_count > 0`         | `<strong>109 items</strong> across 4 brands`                              |
| `so_count > 0`           | `<strong>4 sales orders</strong> totalling $71,182`                       |
| `bom_part_count > 0`     | `<strong>19 BOM parts</strong>`                                           |
| `vendor_count > 0`       | `<strong>5 vendors</strong>`                                              |
| `customer_count > 0`     | `<strong>8 customers</strong>`                                            |
| `corporateSummary.*`     | `<strong>corporate facts</strong>: Solo Brands, Inc. · 327 employees · d2c-multibrand` |
| `state.source === 'user'`| green `you customized this` badge (right side)                            |
| else                     | purple `pre-filled` badge (right side)                                    |

**Conditional rendering rules:**
- If `signals === null && corporateSummary === null` → strip stays hidden (display:none). No "Based on" with empty data.
- If `signals` is present but every count is 0 AND `corporateSummary` is null → strip stays hidden (bits.length === 0 short-circuit).
- Each bit is independently gated — strip can show only sales-orders + corporate-facts if items haven't been imported yet.

## Backwards-Compat Proof

- **Finalize contract:** `POST /api/onboarding/finalize { selected_modules: [...] }` is byte-equal to the pre-rewrite (`grep "onboarding/finalize" recommend.html` shows the exact same `Object.assign`-free literal payload). Cached browsers that load this page from the old S3 cache still hit the unchanged `/finalize` route and succeed.
- **Recommend contract:** `POST /api/onboarding/recommend` is a strict SUPERSET of the old body — old keys (`industry`, `team_size`, `pain_point`, `tools_today`, `asc606_needs`) preserved; only NEW key is `data_signals`. If Plan 02's recommend handler ignores `data_signals` (e.g. during partial rollback), the old answer-driven scorer still works.
- **404 fallback:** if `GET /profile` 404s, the wizard falls back to the original 5-question form embedded as `FALLBACK_QUESTION_SET`. So the page renders normally even if Plan 02 isn't deployed yet — verifying the deploy ordering doesn't strand users mid-flow.
