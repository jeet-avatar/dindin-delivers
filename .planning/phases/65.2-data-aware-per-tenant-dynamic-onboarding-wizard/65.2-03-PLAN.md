Critical points:
- All `<button data-value="...">` are now generated from `state.questionSet.questions` (no hardcoded options).
- `state.answers` is the single source of truth for the UI's selected state. Mutations always also push into `pendingDiff` and call `schedulePatch()`.
- Debounce strategy per Pitfall 8: single `setTimeout` cleared on each click. `pendingDiff` accumulates so multiple field changes in a 400ms window go in ONE PATCH. After the PATCH returns, `state.source` flips to 'user' and the signals strip re-renders to show the green "you customized this" badge.
- The Finalize button payload is BYTE-EQUAL to the existing wizard (selected_modules array). This is the backwards-compat safety net — if the new GET /profile endpoint fails, cached browsers WITH the old JS would still hit /api/onboarding/recommend + /finalize and work normally. The new browser path also still calls /recommend + /finalize unchanged at the top of the funnel.
- The "Show me my modules" button is hidden until profile loads (prevents user clicking before data arrives).
- Empty-state safety: if `state.signals === null` AND `state.corporateSummary === null`, the signals strip stays hidden (display:none). No "💡 Based on" with empty data.

Do NOT introduce any new dependencies (no React, no bundler, no module imports beyond what's already in `<head>`). Pure vanilla JS per the Phase 27+ convention.
