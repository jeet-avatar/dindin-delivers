## Decisions Made

1. **W5 in-memory signal cache (not DB-cached columns).** The plan had a `data_signals_cached jsonb` + `signals_computed_at timestamptz` design earlier, but W5 revision moved the cache to Lambda module scope (`Map<tenantId, {signals, computedAt}>` with 5-min TTL). Cold-start cost of recomputing 6 queries <1s is acceptable per research Pitfall 3. DB row stays simple.
2. **Dollar-quoted JSON literal for backfill.** Using `$body$...$body$` avoids escaping every internal quote, URL semicolon, and special character. The literal is byte-equal to `data/solobrands-corporate.json` (post-Task-3 edit), so future re-syncs are a simple copy-paste.
3. **Uniform value enums across question sets.** Each set has the SAME options for team_size/pain_point/tools_today/asc606_needs. Only labels differ (e.g. aerospace's `compliance-asc606` reads "ASC 606 / AS9100 / ITAR compliance" vs SaaS's "ASC 606 subscription revenue"). This lets the rule engine score additively without per-set branching — sets pick DEFAULTS + ordering, not disjoint schemas (per research §user_constraints item 2).
4. **W3 PRE-FLIGHT verified: no audit_log_v2.action CHECK constraint exists.** Grep of migrations/035*.sql + 036*.sql returned empty. Live DB query against pg_constraint also returned 0 rows. Migration header documents this; no ALTER needed for Plan 02's `onboarding.profile_updated` action.
5. **Applied migration to Aurora during execution (not deferred to Plan 04).** Per success criteria in execution context, Plan 01 must apply via runner Lambda. Verified post-apply with 6 different SELECT checks. Plan 04 will run the smoke harness end-to-end.

## Issues Encountered

1. **First runner Lambda invocation failed with "wrong password" for `zietra_admin`.**
   - **Root cause:** The runner's default user is `zietra_admin` (master role) which lives in the `rds!cluster-16d5e38c-...` AWS-managed secret, NOT in `zietra-aurora/admin-bypass-role` (which is `zietra_admin_bypass`, a separate non-master role).
   - **Resolution:** Fetched the actual `zietra_admin` password from `rds!cluster-16d5e38c-2fc2-4d06-8435-e4b01704bf74` (the secret for the active `zietra-aurora-prod-v2` cluster — confirmed via `aws rds describe-db-proxy-targets`).
   - **Verified:** Listed all 4 tenants via runner Lambda before applying any DDL.
2. **`run-sql.sh` splits on semicolons** — would mangle the dollar-quoted JSON literal which contains semicolons inside URLs and PL/pgSQL DO blocks. Worked around by invoking the runner Lambda **directly** with the entire migration file as a single `event.sql` payload. Runner returned `ok:true` with one harmless notice (DROP POLICY IF EXISTS on non-existent policy).
