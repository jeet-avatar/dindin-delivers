## Decisions Made

See key-decisions in frontmatter. Highlights:

1. **`GET /state` is callable by any authenticated role.** The checklist must render for every tenant user (admin sees Mark-done buttons; members/viewers see read-only). `PATCH /checklist` gates on admin+manager so only workspace-level decision-makers can dismiss steps.
2. **`complete` boolean is computed, not stored.** Auto-detection paths (54.4-01 `/finalize` writes `modules=true`, 54.4-02 migration writes `data=true`) update individual booleans via `jsonb_set` -- if `complete` were stored, it would go stale on every auto-update. Recomputing at read-time on `/state` is O(4) and always consistent.
3. **Frontend masks the `agents` step when `ai-agents` is disabled.** Backend returns raw 4 booleans always; the widget treats `effectiveAgents = agentsEnabled ? cl.agents : true` so the all-4 AND works for 3-step tenants. Avoids backend complexity.
4. **One endpoint extended instead of two new ones.** `GET /api/tenants/current` already loads the tenant row -- adding `onboarding_state` to that SELECT + response is a 2-line change (Rule 6: no unnecessary code). The home page renders the checklist with ONE fetch, not two. `/api/onboarding/state` exists as a standalone for pages that don't want the full tenant payload.
5. **Smoke script counts BOTH styles of CF Function R-map entries.** First implementation only counted `'/onboarding/...'` literals -- missed the 5 `OM+'/...'` concatenations introduced in 54.4-02. Now sums explicit literals + `OM+'/[a-z-]+'` matches to get the true total (7).
