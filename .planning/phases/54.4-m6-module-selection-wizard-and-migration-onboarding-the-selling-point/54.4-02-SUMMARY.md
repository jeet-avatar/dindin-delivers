## Decisions Made

1. **Adapted to actual Aurora schema** — plan referenced non-existent tables (sf_accounts/ns_items/ns_vendors/ns_customers). Verified real schema via netsuite.ts:127/420/450 + salesforce.ts:53 — used turion.{customers,items,vendors} with `(id, [name?,] source_data jsonb, tenant_id)` pattern. CSV columns packed into `source_data` so all existing consumers (api/data/all etc.) read imports for free without code changes.
2. **bypassPool is lazy** — `getBypassPool()` only constructs the pool on first sample-data clone call; saves cold-start time on tenants who never clone. Max 2 connections.
3. **PK remap dictionary scaffolded but unused** — turion.* tables use text PKs unique only per (id, tenant_id), so same `SAT-001` string is fine across tenants. Dictionary stays in place so any future FK-bearing migration can opt in via `fkRewrites` without redesign.
4. **Single vendors page for vendors + customers** — `?type=customers` query param swaps endpoint + labels. One 145-line file instead of two near-identical files (Global Rule 6).
5. **Separate netsuite-clone vs sample-data wizards despite same backend** — different framing for different intents (evaluation vs blank-slate), cheap future divergence.
6. **CF Function compressed via OM prefix** — declared `var OM='/onboarding/migrate'` once, then `R54M = [[OM, OM+'.html'], ...]` x6. Stays under 10240-byte CloudFront limit (final size 10024 bytes).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] PLAN referenced wrong Aurora table names**
- **Found during:** Task 1 (pre-write schema verification)
- **Issue:** Plan specified INSERTs into `turion.sf_accounts`, `turion.ns_items`, `turion.ns_vendors`, `turion.ns_customers` — none of those tables exist in the live Aurora schema. PLAN even called out this risk: "if turion.ns_items or sibling tables have different column names in your Aurora schema, verify via \d turion.ns_items against the live cluster BEFORE writing the INSERTs."
- **Verification:** Aurora not reachable from laptop (private VPC); verified actual schema via reverse-search of backend code: `turion.customers (id, name, source_data, tenant_id)` per netsuite.ts:127 + salesforce.ts:53; `turion.items (id, source_data, tenant_id)` per netsuite.ts:420; `turion.vendors (id, source_data, tenant_id)` per netsuite.ts:450. Salesforce accounts AND NetSuite customers share `turion.customers` already.
- **Fix:** Adapted INSERT targets in `csv-import.ts` + `sf-csv-import.ts` + `sample-data-clone.ts` to use the real table names + the real `(id, [name?,] source_data jsonb, tenant_id)` shape. CSV columns packed into source_data jsonb so every existing reader (api/data/all + per-module routers) sees imported rows immediately without schema migration.
- **Files modified:** 3 new backend files all use correct table names; behavior unchanged from plan's intent.
- **Committed in:** c2cb87f (Task 1 commit) — also documented in the commit body.
