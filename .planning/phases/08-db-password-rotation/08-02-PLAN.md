    ```bash

    cd package && zip -r ../rotation-prod.zip . && cd ..

    aws lambda create-function \
      --function-name dollor-db-rotation \
      --runtime python3.12 \
      --handler rotation_function.lambda_handler \
      --zip-file fileb://rotation-prod.zip \
      --role arn:aws:iam::134607809447:role/dollor-db-rotation-role \
      --timeout 60 \
      --vpc-config SubnetIds=<same-subnet-as-staging>,SecurityGroupIds=<same-sg-as-staging> \
      --region us-east-1
    # If function already exists, use update-function-code

    # The IAM role policy must include the production secret ARN:
    # arn:aws:secretsmanager:us-east-1:134607809447:secret:dollor/production/database-v2-*
    ```

    STEP B — Update redeployment Lambda to include production service.
    Edit `infrastructure/lambda/ecs-redeployment/redeployment_function.py`: add `('dollor-production', 'dollor-api-service')` to the services list so it redeploys BOTH staging and production after any rotation.

    Re-deploy the updated function:
    ```bash
    cd infrastructure/lambda/ecs-redeployment
    zip redeployment.zip redeployment_function.py
    aws lambda update-function-code \
      --function-name dollor-ecs-redeployment \
      --zip-file fileb://redeployment.zip \
      --region us-east-1
    ```

    STEP C — Grant Secrets Manager permission to invoke production rotation Lambda:
    ```bash
    aws lambda add-permission \
      --function-name dollor-db-rotation \
      --statement-id SecretsManagerRotation \
      --action lambda:InvokeFunction \
      --principal secretsmanager.amazonaws.com \
      --region us-east-1
    ```

    STEP D — Create EventBridge rule for production rotation redeployment:
    ```bash
    aws events put-rule \
      --name dollor-db-rotation-prod-redeployment \
      --event-pattern '{
        "source": ["aws.secretsmanager"],
        "detail-type": ["Secrets Manager Secret Rotation Notification"],
        "detail": {
          "eventName": ["EndRotation"],
          "secretId": ["dollor/production/database-v2"]
        }
      }' \
      --state ENABLED \
      --region us-east-1

    aws events put-targets \
      --rule dollor-db-rotation-prod-redeployment \
      --targets '[{"Id":"1","Arn":"arn:aws:lambda:us-east-1:134607809447:function:dollor-ecs-redeployment"}]' \
      --region us-east-1

    aws lambda add-permission \
      --function-name dollor-ecs-redeployment \
      --statement-id EventBridgeProdRotation \
      --action lambda:InvokeFunction \
      --principal events.amazonaws.com \
      --source-arn arn:aws:events:us-east-1:134607809447:rule/dollor-db-rotation-prod-redeployment \
      --region us-east-1
    ```

    STEP E — Enable 30-day rotation schedule on production secret (no --rotate-immediately yet):
    ```bash
    aws secretsmanager rotate-secret \
      --secret-id "dollor/production/database-v2-gd1oKf" \
      --rotation-lambda-arn "arn:aws:lambda:us-east-1:134607809447:function:dollor-db-rotation" \
      --rotation-rules '{"ScheduleExpression": "rate(30 days)"}' \
      --region us-east-1
    ```

    STEP F — Add CloudWatch alarm for rotation Lambda errors:
    ```bash
    aws cloudwatch put-metric-alarm \
      --alarm-name "dollor-db-rotation-failure" \
      --alarm-description "DB rotation Lambda error — check /aws/lambda/dollor-db-rotation logs" \
      --metric-name Errors \
      --namespace AWS/Lambda \
      --dimensions Name=FunctionName,Value=dollor-db-rotation \
      --statistic Sum \
      --period 300 \
      --evaluation-periods 1 \
      --threshold 1 \
      --comparison-operator GreaterThanOrEqualToThreshold \
      --treat-missing-data notBreaching \
      --region us-east-1
    ```

  <action>
    Create `.planning/runbooks/db-rotation.md` with the following sections. Write the content based on the actual ARNs, function names, and secret IDs confirmed in this phase. Do not use placeholders.

    **Section 1: Overview**
    - What rotates: `dollor/production/database-v2-gd1oKf` and `dollor/staging/database-url`
    - Schedule: every 30 days (automatic); next rotation date = LastRotatedDate + 30 days
    - What happens during rotation: 4-step Lambda protocol, then EventBridge triggers ECS force redeployment
    - Zero-downtime: ECS uses rolling update (minimumHealthyPercent=100); old tasks stay up until new tasks are healthy

    **Section 2: Monitoring Checks**
    - Check rotation status: `aws secretsmanager describe-secret --secret-id dollor/production/database-v2-gd1oKf --query '{LastRotatedDate:LastRotatedDate,RotationEnabled:RotationEnabled}'`
    - Check rotation Lambda logs: `aws logs tail /aws/lambda/dollor-db-rotation --since 1h --region us-east-1`
    - Check CloudWatch alarm: `aws cloudwatch describe-alarms --alarm-names dollor-db-rotation-failure`
    - Check ECS service health after rotation: describe-services command for dollor-api-service
    - Check production health: `curl -s https://api.dollor.ai/health`

    **Section 3: Responding to Alarm (dollor-db-rotation-failure)**
    - Step 1: Check Lambda logs for which step failed (createSecret, setSecret, testSecret, finishSecret)
    - Step 2: If setSecret failed — check psycopg2 connection error. Confirm Lambda VPC config matches RDS subnet. If RDS is unreachable, rotation will auto-retry up to 3 times; wait 10 min.
    - Step 3: If finishSecret failed — check if AWSPENDING version exists; manually promote if needed via AWS console or CLI.
    - Step 4: If ECS redeployment did not trigger — manually call: `aws ecs update-service --cluster dollor-production --service dollor-api-service --force-new-deployment --region us-east-1`
    - Step 5: After resolving, confirm health: `curl -s https://api.dollor.ai/health`

    **Section 4: Rollback Procedure**
    - Rotation failure before finishSecret: old password still in AWSCURRENT; no DB access is disrupted; no rollback needed. Fix the Lambda and re-trigger.
    - Rotation completed but ECS not redeployed: tasks still hold old DATABASE_URL which is now the AWSPREVIOUS version. RDS still accepts AWSPREVIOUS password for 24 hours (it is the old current password). Manually trigger redeployment: `aws ecs update-service --cluster dollor-production --service dollor-api-service --force-new-deployment --region us-east-1`
    - Emergency rollback (restore old password): `aws secretsmanager update-secret-version-stage --secret-id dollor/production/database-v2-gd1oKf --version-stage AWSCURRENT --move-to-version-id <AWSPREVIOUS-version-id>` — this requires knowing the previous version ID from `list-secret-version-ids`.
    - To disable rotation temporarily: `aws secretsmanager cancel-rotate-secret --secret-id dollor/production/database-v2-gd1oKf`

    **Section 5: Manual Rotation (on-demand)**
    ```bash
    aws secretsmanager rotate-secret \
      --secret-id "dollor/production/database-v2-gd1oKf" \
      --rotate-immediately \
      --region us-east-1
    ```

    **Section 6: Lambda Function Reference**
    - Rotation Lambda: `dollor-db-rotation` (production), `dollor-db-rotation-staging` (staging)
    - Redeployment Lambda: `dollor-ecs-redeployment`
    - EventBridge rules: `dollor-db-rotation-prod-redeployment`, `dollor-db-rotation-staging-redeployment`
    - CloudWatch alarm: `dollor-db-rotation-failure`
    - Log groups: `/aws/lambda/dollor-db-rotation`, `/aws/lambda/dollor-ecs-redeployment`
