  <action>
    First, confirm the staging secret schema and staging task definition ARN by running:
    ```
    aws secretsmanager get-secret-value --secret-id dollor/staging/database-url --region us-east-1 --query SecretString
    aws ecs describe-task-definition --task-definition dollor-api-staging:29 --region us-east-1 --query 'taskDefinition.containerDefinitions[0].secrets[?name==`DATABASE_URL`]'
    aws rds describe-db-instances --region us-east-1 --query 'DBInstances[*].{id:DBInstanceIdentifier,endpoint:Endpoint.Address}'
    ```
    Record the actual secret key name (confirm `DATABASE_URL`), the staging task def ARN, and the RDS host endpoint.

    Create `infrastructure/lambda/db-rotation/requirements.txt`:
    ```
    psycopg2-binary==2.9.9
    ```

    Create `infrastructure/lambda/db-rotation/rotation_function.py` implementing the 4-step AWS rotation protocol:
    - `lambda_handler(event, context)`: reads `event['Step']` and dispatches to the correct step function. Never raise on unknown step — log and return.
    - `create_secret(client, secret_id, token)`: reads AWSCURRENT, parses `DATABASE_URL` with regex `postgresql://([^:]+):([^@]+)@([^/]+)/(.+)`, generates a 32-char password using `secrets.choice()` with safe charset `string.ascii_letters + string.digits + "!#$%&()*+,-.;<=>?[]^_{}|~"` (no `:/@"\` — these break PostgreSQL URLs), stores as AWSPENDING via `put_secret_value` with `ClientRequestToken=token`.
    - `set_secret(client, secret_id, token)`: reads AWSPENDING, connects to RDS via psycopg2 using the AWSCURRENT credentials (host/port from URL parse), executes `ALTER USER {username} WITH PASSWORD '{new_password}'`. Use autocommit=True. The host is the RDS endpoint discovered above.
    - `test_secret(client, secret_id, token)`: reads AWSPENDING, attempts a psycopg2 connection with the new credentials, runs `SELECT 1`, closes connection. Raises on failure.
    - `finish_secret(client, secret_id, token)`: calls `update_secret_version_stage` to move AWSPENDING to AWSCURRENT and AWSCURRENT to AWSPREVIOUS using the standard atomic promotion pattern.

    IMPORTANT: The `event` dict also contains `ClientRequestToken` at the top level — pass it through to each step as `token`.

    Create `infrastructure/lambda/ecs-redeployment/redeployment_function.py`:
    - `lambda_handler(event, context)`: calls `boto3.client('ecs').update_service` for `('dollor-production', 'dollor-api-staging-service')` only (production service added in 08-02). Log the service name and response `ResponseMetadata.HTTPStatusCode` for each call.

    Do NOT touch `infrastructure/ecs/task-definition.json` — the `DATABASE_URL` key in the secret stays unchanged.
  </action>
  <verify>

<task type="auto">
  <name>Task 2: Deploy Lambdas, wire EventBridge, enable staging rotation</name>
  <files></files>
  <action>
    STEP A — Package and deploy rotation Lambda for staging:
    ```bash
    cd infrastructure/lambda/db-rotation
    pip install -r requirements.txt -t package/
    cp rotation_function.py package/
    cd package && zip -r ../rotation-staging.zip . && cd ..

    # Create Lambda in same VPC as RDS (use subnet/SG from existing Lambda or ECS config)
    # First, get the VPC config used by the ECS tasks:
    aws ecs describe-task-definition --task-definition dollor-api-staging:29 \
      --region us-east-1 \
      --query 'taskDefinition.networkConfiguration.awsvpcConfiguration'

    # Create IAM role for rotation Lambda (or reuse existing if dollor-db-rotation-role exists)
    # The role needs the IAM policy from RESEARCH.md §IAM Policy for Rotation Lambda

    aws lambda create-function \
      --function-name dollor-db-rotation-staging \
      --runtime python3.12 \
      --handler rotation_function.lambda_handler \
      --zip-file fileb://rotation-staging.zip \
      --role arn:aws:iam::134607809447:role/dollor-db-rotation-role \
      --timeout 60 \
      --vpc-config SubnetIds=<subnet-from-ecs>,SecurityGroupIds=<sg-from-ecs> \
      --region us-east-1
    # If function already exists, use update-function-code instead
    ```

    STEP B — Package and deploy ECS redeployment Lambda:
    ```bash
    cd infrastructure/lambda/ecs-redeployment
    zip redeployment.zip redeployment_function.py

    aws lambda create-function \
      --function-name dollor-ecs-redeployment \
      --runtime python3.12 \
      --handler redeployment_function.lambda_handler \
      --zip-file fileb://redeployment.zip \
      --role arn:aws:iam::134607809447:role/dollor-ecs-redeployment-role \
      --timeout 30 \
      --region us-east-1
    # Role needs IAM policy from RESEARCH.md §IAM Policy for ECS Redeployment Lambda
    # The redeployment Lambda does NOT need VPC access (ECS API is public)
    ```

    STEP C — Grant Secrets Manager permission to invoke the rotation Lambda:
    ```bash
    aws lambda add-permission \
      --function-name dollor-db-rotation-staging \
      --statement-id SecretsManagerRotation \
      --action lambda:InvokeFunction \
      --principal secretsmanager.amazonaws.com \
      --region us-east-1
    ```

    STEP D — Create EventBridge rule targeting the Secrets Manager EndRotation event for the staging secret, with dollor-ecs-redeployment as the target:
    ```bash
    aws events put-rule \
      --name dollor-db-rotation-staging-redeployment \
      --event-pattern '{
        "source": ["aws.secretsmanager"],
        "detail-type": ["Secrets Manager Secret Rotation Notification"],
        "detail": {
          "eventName": ["EndRotation"],
          "secretId": ["dollor/staging/database-url"]
        }
      }' \
      --state ENABLED \
      --region us-east-1

    aws events put-targets \
      --rule dollor-db-rotation-staging-redeployment \
      --targets '[{"Id":"1","Arn":"arn:aws:lambda:us-east-1:134607809447:function:dollor-ecs-redeployment"}]' \
      --region us-east-1

    # Grant EventBridge permission to invoke redeployment Lambda
    aws lambda add-permission \
      --function-name dollor-ecs-redeployment \
      --statement-id EventBridgeStagingRotation \
      --action lambda:InvokeFunction \
      --principal events.amazonaws.com \
      --source-arn arn:aws:events:us-east-1:134607809447:rule/dollor-db-rotation-staging-redeployment \
      --region us-east-1
    ```

    STEP E — Enable rotation on staging secret (schedule only, no immediate rotation yet):
    ```bash
    aws secretsmanager rotate-secret \
      --secret-id "dollor/staging/database-url" \
      --rotation-lambda-arn "arn:aws:lambda:us-east-1:134607809447:function:dollor-db-rotation-staging" \
      --rotation-rules '{"ScheduleExpression": "rate(30 days)"}' \
      --region us-east-1
    ```
  </action>
