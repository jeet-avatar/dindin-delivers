Add a small shim to `app-shell.js` that implements the `data-tenant-only` HTML attribute contract. Plan 10 will apply the attribute to narrative-heavy HTML blocks; this shim is what makes those blocks disappear for non-Turion tenants.

**Contract:**
- ANY DOM element carrying `data-tenant-only="<csv-of-slugs>"` is REMOVED from the DOM at page-load time when the current tenant slug is NOT in the CSV.
- Empty / missing attribute value: element is KEPT (treat as "all tenants").
- Tenant fetch fails / unknown slug: element is KEPT (fail-OPEN — never delete content if we can't be sure; this preserves Turion behavior if `/api/tenants/current` is down).
- Runs BEFORE the existing `[data-z-tenant-*]` populator block at line 481, so non-Turion users never see a flash of defense content.
- Idempotent (safe if called twice — once removed, an element can't be removed again).

**Where to insert:** Inside `bootSync()` function's existing body, at the START of the try-block at line 493 (just before the `if (tenant && tenant.name)` populator block). Reason: tenant object is already fetched + populated at this point. The shim needs `tenant.slug`.

**The ~20-LOC shim (insert verbatim, preserving existing style — `var`, ES5-safe, defensive try/catch):**

```js
    // ---- Phase 65.3-09: data-tenant-only gating shim ------------------
    //
    // CONTRACT: any element with `data-tenant-only="<slug1,slug2,...>"`
    // is REMOVED from the DOM if the current tenant.slug is NOT in the
    // comma-separated allow-list. Fails OPEN (keeps the element) when
    // tenant.slug is missing/unknown — preserves existing Turion behavior
    // if the tenant API is down.
    //
    // Purpose: gate Turion-specific aerospace/defense narrative blocks
    // on netsuite-customer-so / netsuite-project-evms / salesforce-account
    // / netsuite-financials / ns-record / arena-bom / netsuite-items /
    // netsuite-procurement / workflow-e2e so Solo Brands + new tenants
    // never render USSF / DCMA / DFARS / ITAR / CMMC / $147.5M FFP /
    // Andromeda / Cape Canaveral / Col. M. Hansen / TUR-FFP-2024-001.
    //
    // Idempotent. Runs BEFORE the [data-z-tenant-*] populator so there is
    // no flash-of-Turion-content for non-Turion tenants. ~20 LOC + comment.
    try {
      var activeSlug = tenant && tenant.slug ? String(tenant.slug).toLowerCase() : '';
      var gated = document.querySelectorAll('[data-tenant-only]');
      for (var g = 0; g < gated.length; g++) {
        var allowAttr = gated[g].getAttribute('data-tenant-only') || '';
        if (!allowAttr) continue; // empty attr → keep
        var allow = allowAttr.split(',').map(function (s) { return s.trim().toLowerCase(); }).filter(Boolean);
        if (allow.length === 0) continue; // malformed → keep
        if (!activeSlug) continue; // tenant fetch failed → fail OPEN, keep
        if (allow.indexOf(activeSlug) === -1) {
          // Not in allow-list — remove from DOM entirely (so it can't be
          // re-shown by later CSS / JS / inspector). parentNode guard for
          // already-detached nodes (idempotency).
          if (gated[g].parentNode) gated[g].parentNode.removeChild(gated[g]);
        }
      }
    } catch (e) { /* fail open — leave any gated content in place */ }
    // ---- end Phase 65.3-09 data-tenant-only shim ----------------------
```

**Where exactly to insert:** After `document.body.appendChild(main);` at line 479 and BEFORE the `try { if (tenant && tenant.name)` populator block at line 493-512. That ordering matters: the populator REWRITES textContent on existing nodes; the gating shim REMOVES nodes. Gate first (so non-Turion never sees the Turion content), then populate the remaining (tenant-neutral) nodes with the tenant name.

**Document the contract at top of app-shell.js:** Add a one-line entry to the comment block at lines 1-13 (just below the existing "Idempotent" line):

Since app-shell.js is loaded with `<script src="/app-shell.js">` (defer/async patterns vary per page), the browser MAY render the body before the shim runs. To mitigate flash:

- The shim runs inside `document.body.appendChild(main);` flow, which is already after `while (document.body.firstChild) main.appendChild(document.body.firstChild);` (line 469).
