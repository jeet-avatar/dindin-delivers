**Step A — app-shell.js shim extension:**

In the existing `data-tenant-only` shim block (added in Plan 09 inside bootSync's try-block), append a parallel pass for the inverse:

```js
      // Phase 65.3-10: inverse — data-tenant-only-fallback panels are the
      // empty-state shown to tenants WITHOUT the Turion narrative. Remove
      // them for any tenant whose slug matches a sibling data-tenant-only
      // allow-list. Simplest correct semantics: if activeSlug is 'turion',
      // remove all [data-tenant-only-fallback] (because Turion sees the
      // gated narrative instead). For non-Turion tenants, keep the fallback
      // (so they see the empty-state).
      //
      // This is a global rule keyed on tenant identity, not on per-element
      // pairing — simpler than walking sibling DOM, and matches the
      // intended UX: Turion → narrative; non-Turion → empty-state.
      var fallbacks = document.querySelectorAll('[data-tenant-only-fallback]');
      for (var f = 0; f < fallbacks.length; f++) {
        // The default contract: fallback is hidden for the "turion" slug
        // (the canonical narrative-owner). To extend to multi-tenant
        // narrative ownership later, read fallbacks[f].getAttribute(
        // 'data-tenant-only-fallback') as a CSV of slugs that should NOT
        // see the fallback. Empty / missing → defaults to 'turion'.
        var hideForAttr = fallbacks[f].getAttribute('data-tenant-only-fallback') || 'turion';
        var hideFor = hideForAttr.split(',').map(function (s) { return s.trim().toLowerCase(); }).filter(Boolean);
        if (activeSlug && hideFor.indexOf(activeSlug) !== -1) {
          if (fallbacks[f].parentNode) fallbacks[f].parentNode.removeChild(fallbacks[f]);
        }
      }
```
