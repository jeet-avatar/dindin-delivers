**The single most important downstream-impacting decision from this plan.**

Per-tenant Cognito test users (`turion-admin@zietra.com`, `solobrands-admin@zietra.com`)
do NOT exist in the `us-east-1_KQuNS85nP` user pool. The plan originally
proposed minting three distinct tokens; the user approved an admin override
on 2026-05-16:

> **All three slots in `/tmp/cognito-tokens-65.3.env` point to the SAME admin
> token for `jeetnair.in@gmail.com`.** The admin user is tenant-agnostic.
> Tenant context flows via:
>   - **Hostname** (`https://turion.zietra.com/...`, `https://solobrands.zietra.com/...`)
>     for Puppeteer/Playwright snapshots.
>   - **X-Tenant-Slug header** for direct curl/API smoke tests.
> NEVER assume the JWT `sub` binds to a tenant.

**Plans 02a/02b/03/04b/05 MUST honor this convention** — any code that
extracts tenant from `idToken.sub` will silently route all traffic to the
admin user's "tenant" (which is nothing — admin is tenant-agnostic).

## Task 2 — Playwright snapshot tool + Turion baseline

**File:** `/Users/jeet/turion-space-demo/scripts/snapshot-turion-erp-views.mjs`
**LOC:** 181 (≥ 60 required), Playwright Chromium, executable.

**Deviation Rule-3 (auto-fix, blocking-issue):** the plan called for
`puppeteer` but turion-space-demo only has `@playwright/test` installed.
Playwright Chromium is functionally equivalent for our use-case
(`browser.newContext` ≡ `createIncognitoBrowserContext`, `page.goto` +
`page.evaluate` API parity). Avoided `npm install puppeteer` side effect.

**Per-page protocol:**
1. `browser.newContext()` — isolated context (no window-global bleed).
2. `addInitScript` seeds full Cognito session into `localStorage['zietra-cognito-erp']`
   so `cognito-auth.js`'s `requireSession()` does NOT redirect to `/erp-login.html`.
3. `goto` with `networkidle` waitUntil, 30s timeout.
4. `waitForFunction('window.__TURION_DATA_SOURCE__ === "live-aws"')` with 8s
   timeout (catches "page rendered but data-loader didn't emit" → `dataReady:false`
   recorded rather than failed).
5. `evaluate` captures `title`, `bodyText[:50KB]`, `rowCounts.{tables,emptyStates}`,
   `hardcodedTokens` (7-token subset), `dataReady`.
6. `ctx.close()` — full teardown.

**Initial fix discovered during execution:** my first snapshot run wrote token
to `localStorage.cognito-id-token` only — that's not the key `cognito-auth.js`
reads. All 34 pages returned the sign-in page (`bodyText = "Sign in with your
work email..."`, 69 chars). Inspecting `https://turion.zietra.com/cognito-auth.js`
showed the canonical key is `zietra-cognito-erp` (ERP) / `zietra-cognito-satellite`
(satellite) and the value is a JSON object `{idToken, accessToken, refreshToken,
expiresAt, email}`. Rewrote the env file with the full Cognito auth result
(ID/Access/Refresh tokens + ExpiresIn) and updated the snapshot tool to seed
that shape. Second run: all 34 pages HTTP 200, dataReady=true, bodyText>500.
