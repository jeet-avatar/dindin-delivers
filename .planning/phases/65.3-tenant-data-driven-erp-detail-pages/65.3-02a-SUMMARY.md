# Phase 65.3 Plan 02a: Refactor Batch C — Sub-batch 02a (8 dashboards + sfhead route) Summary

Wave 2 of Batch C — converted 8 hardcoded-Turion dashboard pages
(programs/cto/cio/mfg/cfo/ceo/sfhead/executive-cockpit) to the Phase 62
`[data-bind]` harness so Solo Brands sees Solo Brands KPIs, Turion sees
Turion KPIs, and new tenants see empty-state CTAs to the import wizard.
Also closes the backend gap by adding `GET /api/dashboards/sfhead`
(mirrors the existing 11 role-based aggregates).

## Task-by-task

### Task 1 — `GET /api/dashboards/sfhead` backend route + dist resync

Backend route was added in a prior session as commit **`d0175b6`** and
fixed in **`6560ef2`** (25P02 transaction-abort guard via
`to_regclass('turion.activities')` probe). This plan's contribution is
the dist resync commit **`fd6e98b`** bringing the local compiled tree
into parity with the deployed Lambda.

Route signature (final):

```ts
// GET /api/dashboards/sfhead
// Returns: {
//   opportunities_total: number,
//   pipeline_value: number,        // SUM(value) WHERE stage NOT ILIKE 'Closed-%' OR 'Closed_%'
//   qualified_leads: number,       // stage ILIKE 'Qualified%' OR 'Proposal%'
//   opportunities_open: number,    // same predicate as pipeline_value
//   accounts_active: number,       // COUNT(DISTINCT account)
//   activities_30d: number | null, // null if turion.activities absent
//   last_updated: string | null    // MAX(updated_at)::text
// }
```
