**Route 1: GET /api/netsuite/coa**
```typescript
r.get('/coa', async (req, res) => {
  try {
    const data = await withTenantClient(req, async (client) => {
      const result = await client.query(
        `SELECT id, source_data FROM turion.gl_accounts ORDER BY id`
      );
      return result.rows.map(row => ({ account: row.id, ...row.source_data }));
    });
    res.json(data);
  } catch (e: any) {
    res.status(500).json({ error: 'coa_query_failed' });  // do NOT leak e.message — Phase 38 hardening
  }
});
```

**Route 2: GET /api/netsuite/tb?period=YYYY-MM** — trial balance aggregate from journal_entries (per RESEARCH Code Examples). Validate period query param with regex `/^\d{4}-\d{2}$/`; 400 if invalid.

**Route 3: GET /api/netsuite/bs?period=YYYY-MM** — balance sheet. Aggregate from `journal_entries` JOIN `gl_accounts` ON gl_account; group by `gl_accounts.source_data->>'type'` (Asset/Liability/Equity).

**Route 4: GET /api/netsuite/pl?period=YYYY-MM** — P&L. Aggregate from `journal_entries` for revenue + expense account types only.

**Route 5: GET /api/netsuite/period-close?period=YYYY-MM** — returns hardcoded 16-step structure (this is PROCESS METADATA, not tenant data, per RESEARCH §"GAPS"). Each step has `{step_number, label, status: 'complete'|'in-progress'|'pending'}`. For tenants with journal entries in the period, derive status by counting JE batches. For empty tenants, return all 16 steps with status='pending'. The 16 labels MUST be the same canonical list across tenants — copy from netsuite-financials.html's existing hardcoded list (audit will tell you exactly where).

**For ALL 5 routes:**
- Use `withTenantClient(req, async (client) => ...)` — non-negotiable per Pitfall 6
- Wrap in `try/catch` returning `{error: 'snake_case_code'}` — never leak `e.message` (Phase 38 hardening pattern)
- For SUM aggregates, cast to numeric to avoid string-concat bugs: `SUM((source_data->>'debit')::numeric)`
- Empty results return `[]` or `{period, lines: []}` (page handles empty-state — do NOT 404 on empty)
