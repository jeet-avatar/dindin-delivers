## Decisions Made

1. **Body-level wrap over per-block wrap** for the 30 newly-gated pages. Plan 10's per-block approach was correct for the 9 narrative-heavy pages (where Turion content + tenant-neutral chrome coexist meaningfully). For the 30 wider-audit pages, body-level wrap is simpler and entirely correct — these pages are 100% Turion-narrative; non-Turion tenants get a clean empty-state CTA.
2. **Per-tenant nav-item filter** (`NAV_TAXONOMY[].tenantOnly`) over duplicating the entire taxonomy per tenant. Single source of truth for nav order; only per-item visibility differs. Preserves CLAUDE.md global rule #4 ("one shell, one nav across modules").
3. **Per-tenant role-label alias** in `dashboard-live-bind.js` instead of changing the `data-z-dashboard-role` attribute. Rationale: the role string ('dcma') is the API routing key (`/api/dashboards/dcma`) — changing it would break backend integration. Display alias is purely cosmetic, gated on `window.__ZIETRA_TENANT.slug === 'turion'`, preserves Turion experience verbatim.
4. **Smoke allowlist extension** over modifying the smoke check to scan rendered DOM. Rationale: the snapshot tool already does rendered-DOM analysis with Playwright (more thorough than the smoke harness's curl + grep). Smoke's job is fast static-source checks; the allowlist correctly captures "this page has Turion content in source but the shim removes it from non-Turion DOMs at runtime, so don't fail on the static check."
5. **Token re-mint mid-execution** when the original Cognito token expired (~1h TTL). Re-minted via `aws cognito-idp admin-initiate-auth` with the admin bypass password from `zietra/admin-bypass-password` secret. Plan 04b pattern.
6. **Quick-339 4-layer guarded teardown** for test65empty. 3 pre-flight RAISE EXCEPTION asserts (target exists, canaries == 4) + 2 post-flight asserts (residue == 0, canaries still == 4) in a single BEGIN..COMMIT block. Partial application impossible.
