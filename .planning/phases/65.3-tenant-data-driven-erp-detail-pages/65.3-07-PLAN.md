<objective>
Fix G2 (NarrativeSubstitutionRaceFix). 7 pages already refactored in Plans 03 / 04b
have a render-ordering race: their runtime text-walker `substitute()` calls fire
BEFORE the data-loader's synchronous table re-render, so the substituted text
gets overwritten back to Turion tokens on Solo Brands. Live snapshot proves
187 Turion-token leaks across the 7 files (arena-bom 71, netsuite-items 33,
netsuite-procurement 30, arena-qms 17, workflow-e2e 16, netsuite-arm 10,
netsuite-financials 10).

Fix is documented and one-line per file: wrap the `substitute()` call (and any
similar text-walker invocation that runs on `turion-data-ready`) in
`requestAnimationFrame(() => substitute())` so it executes AFTER all the
synchronous `turion-data-ready` listeners (including the data-loader's
table re-render) complete.

Purpose: Close G2 user-facing impact — Solo Brands sees zero Turion tokens in
narrative DOM after deploy. Parallel-eligible with Plan 06 (different file sets;
Plan 07 touches only previously-refactored files; Plan 06 only touches
previously-untouched files).

Output: 7 file edits, ~1-3 lines changed per file (find the substitute() call,
wrap with requestAnimationFrame). NO deploy in this plan — Plan 08 owns deploy.
</objective>

    ```js
    window.addEventListener('turion-data-ready', () => {
    ```

    ```js
    window.addEventListener('turion-data-ready', () => {
      requestAnimationFrame(() => substitute());   // <-- defers to next paint
    });
    ```


    ```js
    document.addEventListener('DOMContentLoaded', () => requestAnimationFrame(substitute));
    window.addEventListener('turion-data-ready', () => requestAnimationFrame(substitute));
    ```

    **Pattern 3 (per netsuite-procurement, where substitute is anonymous inline):**
    ```js
    window.addEventListener('turion-data-ready', () => {
      const TOK_SAT = ['S','AT-','001'].join('');
      document.body.innerHTML = document.body.innerHTML.split(TOK_SAT).join(firstItem);
      // ... more substitutions
    });
    ```
    Transform to (wrap the entire body of the listener):
    ```js
    window.addEventListener('turion-data-ready', () => {
      requestAnimationFrame(() => {
        const TOK_SAT = ['S','AT-','001'].join('');
        document.body.innerHTML = document.body.innerHTML.split(TOK_SAT).join(firstItem);
        // ... more substitutions
      });
    });
    ```

    **CRITICAL — must wrap ALL substitution invocations, not just one:**
    Some files (per Plan 03 SUMMARY) have substitution running on multiple
    triggers: `DOMContentLoaded`, `turion-data-ready`, `data-loader/refresh`,
    or `setTimeout` fallback. Each must be wrapped. Use `grep -c
    requestAnimationFrame` after the edit to confirm wrap count matches
    `grep -c substitute\b` (or equivalent for that file's pattern).

    **EXCEPTION — text-walker that runs INSIDE setTimeout already is OK:**
    If a `substitute()` call is already inside `setTimeout(..., 0)` or
    `setTimeout(..., N)` with N≥0, that's functionally equivalent to RAF
    (defers to a later macrotask). Leave those alone. RAF is preferred for
    paint-aligned timing, but setTimeout(0) also fixes the race.

    **EXCEPTION — text-walker NOT on turion-data-ready also OK:**
    If a substitute() call only runs on `DOMContentLoaded` (and not on
    `turion-data-ready`), the race doesn't exist for that invocation
    (data-loader fires `turion-data-ready` AFTER `DOMContentLoaded`).
    However, the data-loader may STILL re-render the table later when
    `/api/data/all` resolves — so even DOMContentLoaded-only substitutions
    can race the async fetch. To be safe, wrap them in RAF too.
