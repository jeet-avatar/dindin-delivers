# Phase 65.3 Plan 02b: Integration Pages + Platform Pages Refactor Summary

Refactored Batch C's 4 integration pages to render tenant-scoped sync-points
+ sync-runs from existing per-tenant API routes (no new backend), and
applied Phase-63 populator wrappers to 3 platform showcase pages so
non-Turion tenants see their brand name in the narrative. Plus a Rule-3
audit-script enhancement and a Rule-1 dead-link removal on the architecture
page.

## What changed

### Task 1 — 4 integration pages (data-driven)

Each of `integration-vendor-ns.html`, `integration-mes-ns.html`,
`integration-arena-ns.html`, `integration-bank-siem.html` was rewritten to
hydrate its sync-points + sync-runs tables from the per-tenant API:

| Page | Sync-points route | Sync-runs route | Backing table |
|---|---|---|---|
| `integration-vendor-ns.html` | `GET /api/vendor/sync-points` | `GET /api/vendor/sync-runs` | `turion.vendor_ns_integrations` + `vendor_sync_runs` (router mounted at `/api/vendor`) |
| `integration-mes-ns.html` | `GET /api/integration/mes/sync-points` | `GET /api/integration/mes/sync-runs` | `turion.mes_ns_integrations` + `mes_sync_runs` |
| `integration-arena-ns.html` | `GET /api/integration/arena/sync-points` | `GET /api/integration/arena/sync-runs` | `turion.arena_ns_integrations` + `arena_sync_runs` |
| `integration-bank-siem.html` | `GET /api/integration/bank/sync-points` | `GET /api/integration/bank/sync-runs` | `turion.bank_ns_integrations` + `bank_sync_runs` |

Every page now carries the standard refactor recipe inline:

```js
function esc(s) { /* HTML-entity guard for tenant-controlled fields */ }
function renderEmptyState(opts) { /* 📭 No <module> yet · Get started → */ }

async function loadFromAPI() {
  const [points, runs] = await Promise.all([
    window.erpApi.get('/integration/<source>/sync-points').catch(() => null),
    window.erpApi.get('/integration/<source>/sync-runs').catch(() => null),
  ]);
  // …  populate window.X globals + render
}

window.addEventListener('turion-data-ready', () =>
  loadFromAPI().then(render).catch(render));
```

Connector-stack tables likewise hydrate from `window.CONNECTOR_STACK_BY_SCOPE`
populated by `data-loader.js`'s `/api/data/all` (also tenant-scoped via RLS).

### Task 2 — 3 platform pages (Phase-63 populator only)

Per the explicit ROADMAP scope-exclusion + RESEARCH §"Platform/marketing
pages", platform pages get the populator pattern ONLY — no data-bind, no
`/api/data/all`, no `erpApi.get`. The page CONTENT is the narrative for
Turion; non-Turion tenants see their brand name swapped via the populator.

| Page | Before | After |
|---|---|---|
| `architecture.html` | `<title>Turion Space · End-to-End Architecture</title>`; 1 wrapped + 1 unwrapped "Turion Space"; 7 unwrapped aerospace identifiers (`SAT-001` × 4, `PROJ-ANDROMEDA` × 1, `Blue Canyon` × 1, `BCT-RW-` not present, `Cygnus` not present) | `<title>` handled by `app-shell.js#rewriteTitle()`; all "Turion Space" + aerospace tokens wrapped in `<span data-z-tenant-name>` / `<span data-z-tenant-instance>`; 2 Turion-only `ns-record.html?id=SAT-001` `<a>` wrappers dropped (dead-link rule) |
| `index.html` | Already Phase-63 wrapped (`<span data-z-tenant-name>your workspace</span>`, `<span data-z-tenant-name>Turion Space</span>` for the Turion-only deep-link callout) | No changes required |
| `admin-index.html` | `<title>Admin · Turion Space</title>`; bare "Turion Space" in the eyebrow `<div>` | `<title>` handled by `rewriteTitle()`; eyebrow now `<span data-z-tenant-name>Turion Space</span>` |

`app-shell.js` is loaded on all 3 pages (verified `architecture.html:58`,
`index.html:83`, `admin-index.html:21`). Its `rewriteTitle(tenant)` swaps
"Turion Space" in `document.title` automatically — `<title>` tags can't
host nested spans so the runtime rewrite is the right fix.

### Task-2.5 — Rule-3 audit script enhancement

The 7 architecture.html violations were ALL inside Phase-63 populator
wrappers — `<span data-z-tenant-instance>SAT-001</span>` etc. The
populator replaces those `textContent` values at runtime per tenant, so
the static literal in the source is the fallback for offline / SEO / JS-
disabled clients, NOT a hardcode. The audit was line-based regex and
flagged them as violations.

`tokenIsWrapped(line, token)` added (39 LOC). For each token occurrence
on a line, walk back to the most recent opening tag; accept ONLY when
EVERY occurrence is inside a tag carrying `data-z-tenant-(name|instance)`.
Tokens in `href` attributes, plain text, or non-populator tags still flag.

Effect on the 02b 7-file set:

| File | Violations before | After this enhancement | After Task-2 source cleanup |
|---|---:|---:|---:|
| `integration-vendor-ns.html` | 0 | 0 | 0 |
| `integration-mes-ns.html` | 0 | 0 | 0 |
| `integration-arena-ns.html` | 0 | 0 | 0 |
| `integration-bank-siem.html` | 0 | 0 | 0 |
| `architecture.html` | 7 | 2 (the 2 `href` literals) | 0 |
| `index.html` | 0 | 0 | 0 |
| `admin-index.html` | 0 | 0 | 0 |
| **TOTAL (7 files)** | **7** | **2** | **0** |

Sitewide drop: 390 → 356 (34 false positives removed, mostly elsewhere
in Batch C dashboards that already had populator wrappers).

### Task-2.6 — Rule-1 dead-link removal on architecture.html

After Task 2's populator wrapping, the audit still flagged 2 violations on
architecture.html — both `<a href="ns-record.html?type=item&id=SAT-001">…</a>`
deep links. The visible text was already wrapped (`<span data-z-tenant-instance>SAT-001</span>`)
so the populator was rewriting it per tenant — but the `href` URL still
pointed at a Turion-only item record. A Solo Brands user clicking would
land on a "Record not found" empty page (dead end).

Per the user's permanent rule "every link leads somewhere useful, no dead
ends": dropped the `<a>` wrapper on both occurrences. Kept the styled
`<span data-z-tenant-instance style="color:#0066b3; border-bottom:1px dotted #0066b3">SAT-001</span>`
so the visual affordance + tenant-instance population both survive.

## Deviations from Plan

### Rule-3 (auto-fix, blocking issue) — audit script enhancement

**Found during:** Task 2 verification — audit re-run on the 7-file set
showed 7 violations remained on architecture.html, all inside Phase-63
populator wrappers. The plan's `>= 80% reduction` gate would have failed
spuriously.

**Fix:** Added `tokenIsWrapped(line, token)` helper to
`scripts/audit-hardcoded-erp.mjs` (+39 LOC). Walks back from each token
occurrence to the nearest opening tag and skips ONLY when EVERY
occurrence on the line is inside a `data-z-tenant-(name|instance)`-
attributed tag. Tokens in `href`, plain text, or non-populator tags still
flag.

**Commit:** `6206c72`

### Rule-1 (bug fix) — Turion-only dead links on architecture

**Found during:** Task 2 verification — even after Rule-3 enhancement,
architecture.html had 2 violations: `id=SAT-001` URL parameters in
`<a href="ns-record.html?type=item&id=SAT-001">…</a>`. The visible text
was correctly wrapped, but the href would 404 for non-Turion tenants.

**Fix:** Dropped both `<a>` wrappers; kept the styled
`<span data-z-tenant-instance>` so the visual affordance + tenant-instance
population survive. No backend, no chrome change.

**Commit:** `6a453a7`

### Rule-1 (clarification, not a fix) — vendor router path

**Found during:** Task 1 implementation. The plan template suggested
`erpApi.get('/integration/vendor/sync-points')`, but actually the vendor
sync data is served by a separate router mounted at `/api/vendor`
(`backend/src/routes/vendor.ts:71`), NOT `/api/integration/vendor`. The
MES/Arena/Bank routes DO live under `/api/integration/*`
(`backend/src/routes/integration.ts:34-41`).

**Resolution:** `integration-vendor-ns.html` uses `/vendor/sync-points` +
`/vendor/sync-runs`; the other 3 use `/integration/{arena,mes,bank}/sync-*`.
Documented in the per-page table above.
