This migration:
1. Drops the old `chk_audit_log_action` (or whatever name it has — query pg_constraint to find it before dropping; use `DROP CONSTRAINT IF EXISTS` for any plausible names).
2. Re-adds an expanded CHECK including `sync_sales_order|sync_ns_invoice|sync_arena_doc|sync_mes_work_order`.
3. Alters `entity_id` from `UUID NOT NULL` to `TEXT NOT NULL` so legacy turion IDs fit.

**Full file:**
```sql
-- 010_expand_audit_log_for_sync.sql · 2026-05-10
-- Phase 25-01: expand turion_satellite.audit_log to support sync events.
-- Two changes:
--   1. action CHECK now allows sync_sales_order|sync_ns_invoice|sync_arena_doc|sync_mes_work_order
--      in addition to the existing delete|restore|status_change|rate_change|fx_seed.
--   2. entity_id is widened UUID -> TEXT so legacy turion IDs (e.g. 'SO-2026-0501',
--      'INV-2025-04-002', '5318-A · Bus integ GA', 'WO-2027-001') fit.
-- Idempotent. Safe to re-run.
-- NOTE: The existing audit_log table is empty in production today (Phase 24 wired the
-- table but nothing has logged yet), so the UUID -> TEXT cast is a no-op.

SET search_path TO turion_satellite, public;

DO $$ BEGIN
  IF current_database() NOT IN ('postgres') THEN
    RAISE EXCEPTION 'Refusing to run on database %', current_database();
  END IF;
END $$;

-- 1. Widen entity_id from UUID to TEXT.
--    Use USING entity_id::TEXT to cast existing values (any UUIDs become their string form).
ALTER TABLE turion_satellite.audit_log
  ALTER COLUMN entity_id TYPE TEXT USING entity_id::TEXT;

-- 2. Drop old action CHECK and replace with expanded list.
--    Phase 24's constraint was created inline by the original CREATE TABLE in 004; its
--    Postgres-assigned name is typically `audit_log_action_check`. Drop both variants
--    defensively in case the name differs across environments.
ALTER TABLE turion_satellite.audit_log
  DROP CONSTRAINT IF EXISTS audit_log_action_check;
ALTER TABLE turion_satellite.audit_log
  DROP CONSTRAINT IF EXISTS chk_audit_log_action;

ALTER TABLE turion_satellite.audit_log
  ADD CONSTRAINT chk_audit_log_action
  CHECK (action IN (
    'delete','restore','status_change','rate_change','fx_seed',
    'sync_sales_order','sync_ns_invoice','sync_arena_doc','sync_mes_work_order'
  ));

COMMENT ON COLUMN turion_satellite.audit_log.entity_id IS
  'TEXT (was UUID until Phase 25 migration 010). Holds either a satellite UUID or a legacy turion text ID like ''SO-2026-0501''. Use entity_type to disambiguate.';

COMMENT ON CONSTRAINT chk_audit_log_action ON turion_satellite.audit_log IS
  'Phase 25 expansion: original 5 actions (delete|restore|status_change|rate_change|fx_seed) plus 4 sync_* actions for cross-system integration audit trail.';
```

**Why each piece:**
- ALTER TYPE with `USING entity_id::TEXT` — UUID-to-TEXT cast in Postgres requires explicit USING; without it ALTER errors.
- Defensive `DROP CONSTRAINT IF EXISTS` for both `audit_log_action_check` (Postgres auto-naming) and `chk_audit_log_action` (manual name) — safest re-runnable approach.
- Re-add as `chk_audit_log_action` — predictable name for future migrations.
- DO NOT add an `entity_text_id` parallel column (rejected design per RESEARCH §Don't Hand-Roll — simpler to widen the existing column).
- DO NOT make entity_id NULLABLE — every audit row still must point to a specific entity.
