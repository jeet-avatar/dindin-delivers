# Phase 23 — Zietra CRM Commercialization

**Goal:** Ship a full CRM + campaign product at `app.zietra.com` by lifting proven code out of a TechCloudPro internal tool and commercializing it as Zietra. Zero rewrites, zero new features — copy, consolidate, rebrand, ship.

**Source:** Internal TCP tool backup at `/Users/jeet/Documents/production-crm-backup/` (read-only — never modified).

**Target:** `apps/zietra/` in monorepo, sibling subfolders `app/` (frontend) + `backend/` (API). Existing marketing site at `apps/zietra/` root stays intact.

**Branch:** `gsd/phase-23-zietra-crm-port`, off `origin/main`, in isolated worktree.

## Hard Rules

1. **Never touch the source repo's production environment** — no EC2 changes, no DB writes, no GitHub pushes to its repo.
2. **Never modify the backup directory** — it's read-only source.
3. **Zero mention of the source product name** in any shipped file — package.json, UI strings, comments, DB names, env vars, docs.
4. **No NetSuite-specific content** — templates/examples that reference NetSuite get genericized or deleted.
5. **Fresh DB** — Zietra Supabase project `lbpkbpfwdpnwlccmlfxn`. No data migration. Prisma schema applied as net-new.
6. **Auth = Supabase** (already wired on Zietra). Drop the source tool's JWT middleware.
