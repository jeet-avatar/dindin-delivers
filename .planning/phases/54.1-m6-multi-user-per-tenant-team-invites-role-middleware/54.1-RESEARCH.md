## User Constraints (from CONTEXT.md)

### Locked Decisions

**`tenant_users` table schema:**
```sql
CREATE TABLE IF NOT EXISTS public.tenant_users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
  cognito_sub TEXT,  -- nullable until invitee accepts (provisioned at first sign-in)
  email TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'member',  -- admin / manager / member / viewer
  status TEXT NOT NULL DEFAULT 'pending',  -- pending / active / suspended / removed
  invited_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  joined_at TIMESTAMPTZ,
  invited_by_cognito_sub TEXT NOT NULL,
  invite_token TEXT,  -- nullable; one-time, expires after 7 days; cleared after use
  invite_expires_at TIMESTAMPTZ,
  CONSTRAINT tenant_users_role_chk CHECK (role IN ('admin', 'manager', 'member', 'viewer')),
  CONSTRAINT tenant_users_status_chk CHECK (status IN ('pending', 'active', 'suspended', 'removed')),
  UNIQUE (tenant_id, email)
);
CREATE INDEX IF NOT EXISTS idx_tenant_users_tenant ON public.tenant_users(tenant_id);
CREATE INDEX IF NOT EXISTS idx_tenant_users_cognito_sub ON public.tenant_users(cognito_sub) WHERE cognito_sub IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_tenant_users_invite_token ON public.tenant_users(invite_token) WHERE invite_token IS NOT NULL;
```

**Owner backfill (in migration 026):** one row per `tenants` row with the owner's email + role=`admin` + status=`active` + joined_at=`tenants.created_at`. For Turion specifically, the 3 historical non-owner users (`gteshnair@gmail.com`, `jm@techcloudpro.com`, `jeetnair.in@gmail.com`) each get a row in Turion's tenant as role=`admin` status=`active`.

**Role matrix:** admin = full (incl. demote other admins + delete tenant); manager = all module data + invite member/viewer only, no billing/role-change; member = own assignments + module data read; viewer = read-only.

**Invite flow:** owner clicks `Invite member` on `/team` → modal `{email, role}` → `POST /api/team/invite` (auth + `requireRole('admin','manager')`) → server inserts `tenant_users` pending row + sends SES invite email with link `https://<slug>.zietra.com/accept-invite?token=<token>` → invitee clicks → `/accept-invite.html` calls `POST /api/team/accept-invite` (PUBLIC, token-authed) → server validates token + creates/looks-up Cognito user via `AdminCreateUser`/`AdminGetUser` + `AdminAddUserToGroup(role)` + updates row to active → browser triggers `cognitoAuth.signInWithMagicLink(email)` → standard sign-in.

**Role middleware:** `backend/src/middleware/role.ts` (NEW in both repos) with `requireRole(...allowed: string[])` that reads role from `tenant_users` (60s cache like `tenantContext`) + falls back to `cognito:groups[0]` if DB lookup fails. Applied per-route on `/api/team/*` routes.

**`/team` page UI:** replace Phase 54 stub with real content — header `Team — N members`, table (name/email, role badge, status, joined date, actions menu), `Invite member` button gated on role >= manager, modal with role dropdown filtered by inviter's role.

**vitest backend test bootstrap:** `cd backend && npm install -D vitest`, `vitest.config.ts` (mirror satellite's shape), `package.json` scripts `test` and `test:watch`, initial test files for `role-middleware`, `invite-flow`, `tenant-users`. Target ≥15 tests this phase.

### 11. Defensive role check (CONTEXT §11)

### 12. Last-admin protection (CONTEXT §12)

Implementation pattern, exactly per CONTEXT:

```ts
// For PATCH /api/team/:id/role to a non-admin role, OR DELETE /api/team/:id:
const { rows } = await pool.query(
  `SELECT COUNT(*)::int AS cnt
     FROM public.tenant_users
     WHERE tenant_id = $1 AND role = 'admin' AND status = 'active' AND id <> $2`,
  [req.tenant.id, targetUserId],
);
if (rows[0].cnt === 0) {
  return res.status(409).json({ error: 'Cannot remove the last admin' });
}
```

Applies to both `PATCH /api/team/:id/role` (when new role !== 'admin') AND `DELETE /api/team/:id` (when target row is itself role=admin status=active).

### 13. Invite-resend idempotency (CONTEXT §13)

In `POST /api/team/invite`, after validation:
```ts
const existing = await pool.query(
  `SELECT id, status FROM public.tenant_users WHERE tenant_id = $1 AND email = $2`,
  [req.tenant.id, email],
);
if (existing.rowCount) {
  const row = existing.rows[0];
  if (row.status === 'active') return res.status(409).json({ error: 'Already a member' });
  if (row.status === 'suspended') return res.status(409).json({ error: 'Member is suspended' });
  if (row.status === 'removed') return res.status(409).json({ error: 'Member was removed; re-invite blocked' });
  // status === 'pending' → resend: UPDATE token + expiry, do not INSERT
  await pool.query(
    `UPDATE public.tenant_users
       SET invite_token = $1, invite_expires_at = $2, role = $3, invited_by_cognito_sub = $4, invited_at = now()
       WHERE id = $5`,
    [newToken, expiresAt, role, req.user.id, row.id],
  );
} else {
  // fresh INSERT path
}
```

### Pattern 1: requireRole middleware (DB lookup + JWT fallback)

**What:** Express middleware that gates a route on the caller's per-tenant role.
**When to use:** Apply per-route on `/api/team/*` AFTER `tenantContext` and `requireAuth` have run.
**Source:** Mirror of `Phase 53 tenantContext` pattern (60s cache) + fallback to existing `requireAuth`'s `req.user.role`.

```ts
// backend/src/middleware/role.ts — Phase 54.1-01
// Mirror file: /Users/jeet/turion-satellite/backend/src/middleware/role.ts
//
// Reads the caller's role from public.tenant_users (60s cache like tenantContext).
// On DB error, falls back to req.user.role (Cognito Groups via auth.ts). If both
// yield no role in the allowed set, returns 403.
import { Request, Response, NextFunction } from 'express';
import { pool } from '../db';

const CACHE_TTL_MS = 60_000;
const NEG_CACHE_TTL_MS = 5_000;
type Entry = { role: string | null; expiresAt: number };
const cache = new Map<string, Entry>();

async function loadRole(tenantId: string, cognitoSub: string): Promise<string | null> {
  const key = `${tenantId}:${cognitoSub}`;
  const now = Date.now();
  const hit = cache.get(key);
  if (hit && hit.expiresAt > now) return hit.role;
  const r = await pool.query<{ role: string }>(
    `SELECT role FROM public.tenant_users
       WHERE tenant_id = $1 AND cognito_sub = $2 AND status = 'active'`,
    [tenantId, cognitoSub],
  );
  const role = r.rowCount ? r.rows[0].role : null;
  cache.set(key, { role, expiresAt: now + (role ? CACHE_TTL_MS : NEG_CACHE_TTL_MS) });
  return role;
}

// Internal helper: invalidate a single (tenant, user) cache entry. Called by
// PATCH /api/team/:id/role and DELETE /api/team/:id handlers after a mutation.
export function invalidateRoleCache(tenantId: string, cognitoSub: string): void {
  cache.delete(`${tenantId}:${cognitoSub}`);
}

declare global {
  // eslint-disable-next-line @typescript-eslint/no-namespace
  namespace Express {
    interface Request {
      role?: string;
    }
  }
}

export function requireRole(...allowed: string[]) {
  return async (req: Request, res: Response, next: NextFunction): Promise<void> => {
    if (!req.user || !req.tenant) {
      res.status(401).json({ error: 'Authentication and tenant context required' });
      return;
    }
    let role: string | null = null;
    try {
      role = await loadRole(req.tenant.id, req.user.id);
    } catch (e: any) {
      // DB unreachable — fall back to JWT-derived role (cognito:groups[0]).
      console.error('[requireRole] DB lookup failed, falling back to JWT role:', e?.message);
      role = req.user.role || null;
    }
    if (!role) {
      // Defensive: still no role even with fallback.
      res.status(403).json({ error: 'No tenant membership', actual: 'none' });
      return;
    }
    if (!allowed.includes(role)) {
      res.status(403).json({ error: 'Insufficient role', required: allowed, actual: role });
      return;
    }
    req.role = role;
    next();
  };
}
```

### Pattern 2: Atomic invite endpoint with Cognito cleanup

**What:** `POST /api/team/invite` inserts a pending row, sends SES email, and on email failure logs and still returns 200 (per CONTEXT autonomous mode).
**When to use:** Inviting a NEW member. For resends (existing pending row), use UPDATE not INSERT.
**Source:** Mirror of Phase 52 signup pattern in `routes/tenants.ts`.

```ts
// backend/src/routes/team.ts — Phase 54.1-02 (excerpt)
import { Router } from 'express';
import { randomBytes } from 'crypto';
import { pool } from '../db';
import { tenantContext } from '../middleware/tenant';
import { requireAuth } from '../middleware/auth';
import { requireRole } from '../middleware/role';
import { sendEmail } from '../lib/ses-send';

const r = Router();
const EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const ROLES = ['admin', 'manager', 'member', 'viewer'] as const;

// GET /api/team — list members
r.get('/', tenantContext, requireAuth, requireRole('admin', 'manager', 'member', 'viewer'), async (req, res) => {
  const rows = await pool.query(
    `SELECT id, email, role, status, invited_at, joined_at, cognito_sub
       FROM public.tenant_users
       WHERE tenant_id = $1
       ORDER BY status, invited_at`,
    [req.tenant!.id],
  );
  res.json({ members: rows.rows });
});

// POST /api/team/invite — invite or resend
r.post('/invite', tenantContext, requireAuth, requireRole('admin', 'manager'), async (req, res) => {
  const email = String(req.body?.email || '').trim().toLowerCase();
  const role = String(req.body?.role || '').trim().toLowerCase();
  if (!EMAIL_RE.test(email)) return res.status(400).json({ error: 'Valid email required' });
  if (!ROLES.includes(role as any)) return res.status(400).json({ error: 'Invalid role' });
  // Self-invite guard
  const inviter = await pool.query(
    `SELECT email FROM public.tenant_users WHERE tenant_id = $1 AND cognito_sub = $2 AND status = 'active'`,
    [req.tenant!.id, req.user!.id],
  );
  const inviterEmail = inviter.rows[0]?.email;
  if (inviterEmail && email === inviterEmail.toLowerCase()) {
    return res.status(400).json({ error: 'You cannot invite yourself' });
  }
  // Role-promotion guardrail
  if (req.role === 'manager' && (role === 'admin' || role === 'manager')) {
    return res.status(403).json({ error: 'Managers can only assign member or viewer roles' });
  }
  // Idempotency: existing row?
  const existing = await pool.query(
    `SELECT id, status FROM public.tenant_users WHERE tenant_id = $1 AND email = $2`,
    [req.tenant!.id, email],
  );
  const token = randomBytes(32).toString('base64url');
  const expiresAt = new Date(Date.now() + 7 * 24 * 3600 * 1000);
  let rowId: string;
  if (existing.rowCount) {
    const row = existing.rows[0];
    if (row.status === 'active') return res.status(409).json({ error: 'Already a member' });
    if (row.status !== 'pending') return res.status(409).json({ error: `Cannot re-invite ${row.status} member` });
    await pool.query(
      `UPDATE public.tenant_users
         SET invite_token = $1, invite_expires_at = $2, role = $3, invited_by_cognito_sub = $4, invited_at = now()
         WHERE id = $5`,
      [token, expiresAt, role, req.user!.id, row.id],
    );
    rowId = row.id;
  } else {
    const ins = await pool.query(
      `INSERT INTO public.tenant_users
         (tenant_id, email, role, status, invited_by_cognito_sub, invite_token, invite_expires_at)
         VALUES ($1, $2, $3, 'pending', $4, $5, $6) RETURNING id`,
      [req.tenant!.id, email, role, req.user!.id, token, expiresAt],
    );
    rowId = ins.rows[0].id;
  }
  // Best-effort SES (CONTEXT §autonomous mode — don't fail invite on SES error)
  try {
    const acceptUrl = `https://${req.tenant!.slug}.zietra.com/accept-invite?token=${token}`;
    await sendEmail({
      to: email,
      subject: `You're invited to join ${req.tenant!.name} on Zietra`,
      textBody: `${inviterEmail} invited you to join ${req.tenant!.name} as ${role}.\n\nClick to accept: ${acceptUrl}\n\nLink expires in 7 days.`,
      htmlBody: /* ...HTML template... */ '',
    });
  } catch (e: any) {
    console.warn('[invite] SES send failed (invite row still created):', e?.message);
  }
  res.json({ ok: true, invite_id: rowId, email, role, status: 'pending' });
});
```

```ts
// POST /api/team/accept-invite — PUBLIC, no requireAuth
r.post('/accept-invite', async (req, res) => {
  const token = String(req.body?.token || '').trim();
  if (!token || token.length < 32) return res.status(400).json({ error: 'Invalid token' });

  const found = await pool.query(
    `SELECT tu.id, tu.tenant_id, tu.email, tu.role, tu.invite_expires_at, t.slug, t.name
       FROM public.tenant_users tu
       JOIN public.tenants t ON t.id = tu.tenant_id
       WHERE tu.invite_token = $1 AND tu.status = 'pending'`,
    [token],
  );
  if (!found.rowCount) return res.status(410).json({ error: 'Invite expired or already used' });
  const row = found.rows[0];
  if (new Date(row.invite_expires_at).getTime() < Date.now()) {
    return res.status(410).json({ error: 'Invite expired' });
  }

  // Cognito: create user if not exists; add to group matching role
  const USER_POOL_ID = getCognitoUserPoolId();
  let cognitoSub: string | null = null;
  try {
    // Try AdminGetUser first (cheap check)
    try {
      const g = await cognito.send(new AdminGetUserCommand({
        UserPoolId: USER_POOL_ID, Username: row.email,
      }));
      cognitoSub = g.UserAttributes?.find(a => a.Name === 'sub')?.Value ?? null;
    } catch (e: any) {
      if (e?.name !== 'UserNotFoundException') throw e;
      // Create user
      const c = await cognito.send(new AdminCreateUserCommand({
        UserPoolId: USER_POOL_ID, Username: row.email,
        MessageAction: 'SUPPRESS',
        UserAttributes: [
          { Name: 'email', Value: row.email },
          { Name: 'email_verified', Value: 'true' },
          { Name: 'custom:role', Value: row.role },
        ],
      }));
      cognitoSub = c.User?.Attributes?.find(a => a.Name === 'sub')?.Value ?? null;
      const tmpPassword = randomBytes(24).toString('base64url') + 'A1!';
      await cognito.send(new AdminSetUserPasswordCommand({
        UserPoolId: USER_POOL_ID, Username: row.email, Password: tmpPassword, Permanent: true,
      }));
    }
    await cognito.send(new AdminAddUserToGroupCommand({
      UserPoolId: USER_POOL_ID, Username: row.email, GroupName: row.role,
    }));
  } catch (e: any) {
    console.error('[accept-invite] Cognito failed:', e?.name, e?.message);
    return res.status(500).json({ error: 'Failed to provision account' });
  }

  await pool.query(
    `UPDATE public.tenant_users
       SET cognito_sub = $1, joined_at = now(), status = 'active',
           invite_token = NULL, invite_expires_at = NULL
       WHERE id = $2`,
    [cognitoSub, row.id],
  );

  res.json({ ok: true, email: row.email, tenant_slug: row.slug, tenant_name: row.name });
});
```

### Anti-Patterns to Avoid

- **DON'T** call `AdminInitiateAuth` from the invite endpoint. That ties the Cognito session to Lambda memory (the same bug that broke prod signup in Phase 52 hotfix #29). Use a standalone token-authed `accept-invite` page.
- **DON'T** hash the invite token client-side. Plaintext token in DB + HTTPS link is fine for demo-grade per CONTEXT §6. M8 hashes.
- **DON'T** add a global `requireRole` middleware at app.ts level. Apply per-route alongside `tenantContext` + `requireAuth` (mirror Phase 53 pattern).
- **DON'T** modify the existing `requireRole(...roles)` in `middleware/auth.ts`. That helper checks JWT-only and is used by Dollor.ai legacy routes. Phase 54.1 adds a NEW `middleware/role.ts` file (different name OK because it's a different export). If desired, the auth.ts version can be renamed in 54.3 cleanup.
- **DON'T** include the `manager`/`member`/`viewer` groups in the `custom:role` attribute by default. Use `cognito:groups` (via `AdminAddUserToGroup`) — that's the path `auth.ts:getRoleFromCognitoJwt` already prefers.
- **DON'T** clear the `invite_token` immediately on email send. Clear it on successful `accept-invite` ONLY. Otherwise resend (idempotent) can't work.
- **DON'T** include `DELETE` on routes that demote the calling user without an explicit "remove yourself" UX. CONTEXT §9 says admins can't delete themselves — enforce server-side.
- **DON'T** put the invite token in a JWT. It's an opaque single-use ticket, not a credential. Just `randomBytes(32).toString('base64url')`.

## Common Pitfalls

### Pitfall 1: `tenant_users` UNIQUE on `(tenant_id, email)` blocks idempotent resend

**What goes wrong:** Naive `INSERT … ON CONFLICT DO NOTHING` returns 0 affected rows on resend; the new token never lands; invitee sees old expired token.
**Why it happens:** UNIQUE constraint fires, INSERT no-ops, application never UPDATEs.
**How to avoid:** Pre-SELECT by `(tenant_id, email)`; if row exists AND status='pending', UPDATE; if status='active', return 409; if 'suspended'/'removed', return 409. See CONTEXT §13 + Pattern 2 above.
**Warning signs:** "I sent another invite but they still see expired" reports in QA.

### Pitfall 2: Migration backfill INSERT … SELECT runs before tenants exist (cold DB)

**What goes wrong:** Running 026 against an empty DB inserts zero rows; later when 024 runs, owners never get backfilled.
**Why it happens:** Migrations are out of order on a fresh DB.
**How to avoid:** Always run 024 → 025 → 026 in order; `IF NOT EXISTS` guards make 024/025 safe to re-run; the 026 backfill `INSERT … SELECT … ON CONFLICT DO NOTHING` is no-op on a re-run.
**Warning signs:** Local-dev fresh-DB bootstrap drops tenant_users rows but keeps tenants.

### Pitfall 3: Cognito group name vs role value mismatch

**What goes wrong:** Backend stores role=`Admin`, group is `admin`; `AdminAddUserToGroup` 404s.
**Why it happens:** Case differences between DB enum and Cognito group name.
**How to avoid:** Lowercase everything: DB CHECK constraint already enforces lowercase (`'admin'`, etc.); Cognito groups created in step 2 are lowercase. Validate at API boundary: `String(req.body.role).toLowerCase()`.
**Warning signs:** `GroupNotFoundException` from `AdminAddUserToGroup` during accept-invite.

### Pitfall 4: 60s role cache hides role changes

**What goes wrong:** Admin demotes user; user still has elevated rights for up to 60s.
**Why it happens:** Cache TTL.
**How to avoid:** Export `invalidateRoleCache(tenantId, cognitoSub)` from `role.ts`; call it from `PATCH /api/team/:id/role` and `DELETE /api/team/:id` handlers after the DB write. Pattern shown in Pattern 1.
**Warning signs:** Test "admin demotes user, user immediately blocked" fails intermittently.

### Pitfall 5: Last-admin protection race condition

**What goes wrong:** Two admins each call DELETE on each other concurrently; both see count=1 and proceed; tenant ends up with 0 admins.
**Why it happens:** Read-then-write without locking.
**How to avoid:** Use a single `WITH … FOR UPDATE` or `UPDATE … WHERE NOT EXISTS (SELECT 1 ... )` atomic pattern. Or accept the race for demo-grade (very unlikely with 2-admin tenant + 1-second human reaction time). CONTEXT §12 specifies the SQL; for demo-grade, the count check inside a single statement is acceptable.
**Warning signs:** Manual test with two browser tabs deleting each other's accounts.

### Pitfall 6: SES sandbox blocks invite to unverified address

**What goes wrong:** Inviting `foo@example.com` from sandbox SES fails with "Email address is not verified."
**Why it happens:** SES production access not yet granted (per zietra-platform-milestone-kickoff handover — pending User in Console).
**How to avoid:** CONTEXT §autonomous mode says: "Defer with log if SES sandbox blocks." Endpoint returns 200 + DB row created + logs warn. Out-of-sandbox is M3-time.
**Warning signs:** CloudWatch warn `[invite] SES send failed (invite row still created)`.

### Pitfall 7: Token in URL leaks to referrer headers / browser history

**What goes wrong:** Invitee clicks invite link, accepts, then visits another site — Referer header sends the token to the third party.
**Why it happens:** Default browser behavior.
**How to avoid:** `accept-invite.html` MUST include `<meta name="referrer" content="no-referrer">` in `<head>`. Also clear the URL via `history.replaceState(null, '', '/accept-invite')` after parsing the token.
**Warning signs:** Token rotation log shows multiple POSTs from same invitee.

### Pitfall 8: Phase 53 tenantContext middleware requires `X-Tenant-Slug` header

**What goes wrong:** `accept-invite` endpoint is mounted under `/api/team`; the team router includes routes that use `tenantContext`. If `accept-invite` is ALSO mounted under the team router, it'll require `X-Tenant-Slug` — but the invitee doesn't know the slug yet.
**Why it happens:** Express router middleware composition.
**How to avoid:** Either (a) split `accept-invite` into a separate router mounted at a different path that doesn't apply `tenantContext`, OR (b) mount `accept-invite` directly on the app, OR (c) within the team router, register the public route FIRST (before `router.use(tenantContext)`). CONTEXT §scope mentions `routes/invites.ts` as separate file — that's the cleanest split.
**Warning signs:** `accept-invite` returns 400 "Missing X-Tenant-Slug header" instead of 200.

### Pitfall 9: Phase 54 inject-shell.mjs is idempotent — don't break the marker

**What goes wrong:** Editing `team.html` removes the `<!-- ZIETRA-SHELL-INJECTED -->` marker; next inject-shell run double-injects.
**Why it happens:** Marker is a one-line HTML comment; easy to accidentally delete during rewrite.
**How to avoid:** Replace ONLY `<main class="z-stub">...</main>` body content. Preserve `<head>` byte-for-byte (or only ADD safe additions inside `<head>`). Run `node scripts/inject-shell.mjs` after the rewrite to verify it reports `already: 81, injected: 0`.
**Warning signs:** `inject-shell.mjs` reports `injected: 1` on re-run when it should be 0.

### Pitfall 10: CloudFront Function approaching 10 KB cap

**What goes wrong:** Adding too many rewrites pushes the function past 10240 B; CloudFront refuses to publish.
**Why it happens:** Hard CF limit.
**How to avoid:** Current size 9714 B; one-line `/accept-invite` add is ~50 B; safe to ~9764 B. Don't add more in 54.1 — defer to 54.3 cleanup.
**Warning signs:** `update-function` returns `FunctionSizeLimitExceeded`.

### Pitfall 11: Mounting order in app.ts — `/api/team` must come AFTER `requireAuth`-using public routes BUT before catch-all 404

**What goes wrong:** If `/api/team/accept-invite` is mounted after a `requireAuth`-wrapped router that uses a wildcard, requests get 401'd before reaching the public route.
**Why it happens:** Express middleware order.
**How to avoid:** Mount in `app.ts` near the other public routes:
```ts
app.use('/api/tenants', tenants);  // existing — public
app.use('/api/team', team);         // NEW — public for /accept-invite, requireAuth per-route for others
```
`/api/team` router's internal route order: declare `r.post('/accept-invite', ...)` BEFORE any `r.use(tenantContext, requireAuth, ...)`.
**Warning signs:** `accept-invite` returns 401.
