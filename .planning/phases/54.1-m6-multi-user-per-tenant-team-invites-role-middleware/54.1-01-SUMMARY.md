## Decisions Made

1. **TypeScript `any` → `unknown` in catch block.** RESEARCH.md showed `e: any` then `e?.message`. The middleware uses `e: unknown` + `e instanceof Error ? e.message : String(e)` which compiles under both repos' strict tsconfig without `@typescript-eslint/no-explicit-any` lint warnings. Functionally equivalent; safer.
2. **Cognito groups created BEFORE the role middleware was wired into any route.** This avoids any race where the JWT-fallback path tries to find a group that doesn't exist. The middleware's JWT-fallback reads `req.user.role` (already populated by `auth.ts:requireAuth` from `cognito:groups[0]`) — that string just needs to be in the `allowed` list to pass.
3. **`invited_by_cognito_sub` for owner-self-invite rows is set to the owner's own sub.** This is semantically correct ("owner invited themselves at tenant-creation time") and avoids needing a NULLable column or sentinel value.

## Deviations from Plan

None — plan executed exactly as written. The only minor adjustment was using `e: unknown` + `instanceof Error` narrowing in the catch block instead of `e: any` + `e?.message`. This is a pure code-quality improvement (avoids `@typescript-eslint/no-explicit-any` warnings) with identical runtime behavior.
