## Decisions Made

1. **`erpApi.del` not `erpApi.delete`** — The plan's reference snippet used `await window.erpApi.delete(...)`. But `erp-api.js` exports `del` (line 81: `del: (path) => api(path, { method: 'DELETE' })`). The word `delete` is a JS reserved word, hence the abbreviation. Used `erpApi.del` in `team.html` — the Remove button now actually works.
2. **Used `cloudfront-js-1.0` runtime via existing helper script** — The plan suggested calling `aws cloudfront update-function` inline with `Runtime=cloudfront-js-2.0`. But the existing CF Function uses 1.0, and `scripts/update-cf-function.sh` is the established + idempotent helper (byte-cap pre-flight + diff-skip + ETag rotation). Switching runtime mid-flight would be an architectural change outside this plan's scope.
3. **Added `accept-invite.html` to `inject-shell.mjs` SKIP_FILES** — Without this, the next time anyone runs `node scripts/inject-shell.mjs` (e.g., during a future plan that adds a new ERP page), `accept-invite.html` would receive the auth-required app shell. The shell calls `requireSession()` which would redirect the unauthenticated invitee to `/erp-login.html` BEFORE the token-acceptance script could run. Catastrophic UX bug. Caught + fixed at write time (Rule 3 — auto-fix blocking issue).
4. **Used both `turionspace.zietra.com` AND `turion.zietra.com` for smoke** — `turion` is in the CF Function `RESERVED` map but explicitly allowed through (`if (RESERVED[slug] && slug !== 'turion')`). Verified both serve identically; the production canonical is `turionspace.zietra.com` (per CLAUDE.md / app shell config).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `erpApi.delete` → `erpApi.del` in team.html Remove handler**
- **Found during:** Task 1 (writing team.html)
- **Issue:** Plan reference code called `await window.erpApi.delete(...)` but `erp-api.js:81` exports the method as `del` (because `delete` is a JS reserved word and would shadow the operator).
- **Fix:** Changed `erpApi.delete` → `erpApi.del` in team.html. Verified by `grep -E "erpApi\.(del|delete)\(" team.html` — only `del` matches.
- **Files modified:** /Users/jeet/turion-space-demo/team.html (single call site)
- **Commit:** 2e2f443 (Task 1)

**2. [Rule 3 - Blocking] `accept-invite.html` would have been auto-shell-injected**
- **Found during:** Task 2 (after writing accept-invite.html, ran `inject-shell.mjs --dry`)
- **Issue:** `inject-shell.mjs` walks every root-level `.html` file not in `SKIP_FILES`. `accept-invite.html` is a NEW root-level file → would have received `app-shell.css + app-shell.js + ZIETRA-SHELL-INJECTED` injection. The shell calls `requireSession()` synchronously, which would redirect the unauthenticated invitee to `/erp-login.html` BEFORE the token-acceptance script could run — completely breaking the invite flow.
- **Proof:** `node scripts/inject-shell.mjs --dry` before fix → `total=86, already=85, would-injected: 1`.
- **Fix:** Added `'accept-invite.html'` to the `SKIP_FILES` set in `scripts/inject-shell.mjs` (alongside the 3 other public/auth pages: signup.html, cognito-auth-callback.html, erp-login.html).
- **Proof of fix:** `node scripts/inject-shell.mjs --dry` after fix → `total=85, already=85` (accept-invite skipped, no injections needed).
- **Files modified:** /Users/jeet/turion-space-demo/scripts/inject-shell.mjs
- **Commit:** 2b3af79 (Task 2 — bundled with the file create)
