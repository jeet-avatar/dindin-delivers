- [Phase 24-03]: Cost-table supersede uses single CTE; decisions-table supersede uses 3-step BEGIN/COMMIT transaction. Reason: Postgres checks partial UNIQUE indexes per-row at INSERT and partial indexes are NOT deferrable. The single CTE on make_buy_decisions (which has `uq_make_buy_decisions_current WHERE superseded_by IS NULL`) would briefly hold two NULL-superseded rows mid-statement and the new INSERT would collide with the existing live row. The 3-step transaction (UPDATE old.superseded_by=old.id → INSERT new with NULL → UPDATE old.superseded_by=new.id) has identical atomicity (BEGIN/COMMIT) and avoids the constraint conflict. Cost tables (make_costs, buy_costs) deliberately omit the partial UNIQUE per 24-01 design, so the CTE works there as written.
